    第 3 章 · 公钥密码 · 复习资料¶

    对应课件：w3/public-key-cryptography.pdf

    建议用时：第一遍 80 分钟 + 例题 40 分钟 + 自测 30 分钟

    配套：知识大纲 §2.4

    本章权重：RSA 计算、DH 协商、签名/证书、哈希生日界是计算题与简答题的高频来源；Shor 算法常与第 2 章 Grover 对比考。

    0. 本章主线（先记住这三句）¶

    1. 公钥密码用陷门单向函数解决“密钥怎么安全分发”的问题：加密用公钥、解密用私钥；签名反过来。
    2. RSA 的安全性 = 大整数分解；DH 的安全性 = 离散对数；两者都怕 Shor 算法，对称密码只受 Grover 影响。
    3. 公钥算法慢且有消息长度限制，实际系统是“公钥建钥 + 对称加密数据”的混合体制；公钥的“身份绑定”靠 PKI/证书，大消息的签名靠先哈希。

    本章常见考法

    题型 典型问法 备考动作
    RSA 计算 给小 p、q、e，求 d、加密、解密、签名 会扩展欧几里得/试算，会反复平方
    协议分析 DH 为什么怕中间人？怎么防？ 画三方密钥表
    概念辨析 签名 vs MAC；加密 vs 签名 抓“密钥是否共享”
    哈希计算 生日攻击代价、哈希链第 d 次的值 记 \(2^{N/2}\) 与下标
    PKI 证书里有什么？CA 为什么可信？ 背 X.509 字段 + 信任链

    1. 核心思想¶

    1.1 陷门单向函数（trapdoor one-way function）¶

    • 单向：正向容易，反向极难。
    • 陷门：掌握某个秘密（私钥）后，反向变容易。
    • 典型：\(N = p\cdot q\) 容易；由 N 分解出 p、q 极难。陷门就是 p、q。

    1.2 两种用法（必须分清）¶

    目的 发送方用什么 接收方用什么 提供
    加密（保密） Bob 的公钥 Bob 的私钥 机密性
    签名（认证） Alice 的私钥 Alice 的公钥 完整性 + 认证 + 抗抵赖

    记忆：加密是“用对方的公钥锁”，签名是“用自己的私钥盖”。

    2. RSA¶

    2.1 密钥生成 ★★¶

    1. 选两个大素数 p、q。
    2. \(N = p\cdot q\)（模数）。
    3. 计算 \(\varphi (N) = (p-1)(q-1)\)。
    4. 选 e，使 \(\gcd(e, \varphi (N)) = 1\)（通常 e=65537）。
    5. 求 d，使 \(e\cdot d \equiv 1 \pmod{\varphi (N})\)（扩展欧几里得）。
    6. 公钥 (N, e)；私钥 d（p、q 必须保密/销毁）。

    2.2 加解密 ★★¶

    加密：\(C = M^e \bmod N\)；解密：\(M = C^d \bmod N\)。

    正确性直觉：\(C^d = M^{ed} = M^{1+k\varphi (N)} \equiv M \pmod{N}\)；当 gcd(M,N)=1 时由欧拉定理直接得到，不互素时用 CRT 也可证明（因 N 是两个素数之积）。实际中 M 不与 N 互素的概率可忽略。

    2.3 安全性 = 分解 N ★★¶

    • 若攻击者能分解 \(N = p\cdot q\)，就能算出 \(\varphi (N)\)，再由 e 求出 d。
    • 因此：分解模数即破 RSA。
    • 但“RSA 难 ≠ 分解难”是未证明的等价关系；目前没有比分解更快的通用攻击。

    2.4 效率：反复平方（repeated squaring）★¶

    直接算 \(M^e\) 会产生天文数字；必须每步取模。

    例：算 \(5^{20} \bmod 35\)。

    15¹  = 5
25²  = 25
35⁴  = 25² = 625 ≡ 30 (mod 35)
45⁵  = 5⁴·5 = 30·5 = 150 ≡ 10
55¹⁰ = 10² = 100 ≡ 30
65²⁰ = 30² = 900 ≡ 25
    • 先把指数写成二进制，逐位“平方，遇 1 再乘底数”。
    • 中间值始终 < N²，不会爆炸。
    • 可预计算常用幂的表。

    2.5 消息长度与混合加密 ★★¶

    • RSA 只能加密比 N 小的数；2048-bit 模数 = 256 字节。
    • 实际填充（如 PKCS#1 v1.5）还要占 11 字节 → 最多约 245 字节明文。
    • 不要“把消息切块分别 RSA”：密文膨胀、速度慢、还有填充/模式问题。
    • 混合加密（hybrid）：
    • 用 RSA 加密一个随机的对称密钥（或协商密钥）；
    • 用 AES 等对称密码加密真正的数据。
    • SSL/TLS、OpenPGP 都这么做。
    • 但“Bob 怎么确认公钥真是 Alice 的？” → 需要证书（§5）。

    2.6 RSA 数字（了解）¶

    • RSA Labs 发布 100–617 位十进制的半素数（semiprime，恰有两个素因子）。
    • 截至 2018-08，54 个中 20 个被分解。
    • RSA-100（330 bit）最容易；RSA-2048 目前无人能破。
    • 密钥碰撞：两对独立生成的 RSA 密钥恰好相同的概率极低（课件只作非形式说明，不必深究）。
    • 结论：现实部署至少 2048-bit，逐步向 3072/4096 迁移。

    2.7 Textbook RSA 的坑（补充，但常考“为什么需要填充”）¶

    • 确定性：同一 M 永远同一 C → 可做字典/重放；需随机填充（OAEP）。
    • 可延展：\(C_{1}\cdot C_{2} = (M_{1}\cdot M_{2})^e\) → 攻击者可构造相关明文。
    • 签名可伪造：\(S(M_{1})\cdot S(M_{2}) = S(M_{1}\cdot M_{2})\) → 攻击者可不经询问得到 \(M_{1}\cdot M_{2}\) 的签名；需 hash + padding。
    • 小 e / 共模 / 低熵明文：都有经典攻击（本课不展开）。

    3. Diffie-Hellman 密钥交换 ★★¶

    3.1 协议¶

    公开参数：大素数 p、生成元 g。

    1. Alice 选私密 a，计算 \(A = g^a \bmod p\)，发给 Bob。
    2. Bob 选私密 b，计算 \(B = g^b \bmod p\)，发给 Alice。
    3. Alice 算 \(K = B^a = g^{ab} \bmod p\)。
    4. Bob 算 \(K = A^b = g^{ab} \bmod p\)。
    5. 双方得到相同的对称密钥 K。

    DH 不用于加密/签名，只用于协商密钥。

    3.2 安全性 = 离散对数¶

    • 攻击者能看到 \(g, p, A=g^a, B=g^b\)。
    • 若能从 \(g^a\) 求出 a（离散对数问题），就能算 \(K = B^a\)。
    • 注意：\(A\cdot B = g^{a+b} \neq g^{ab}\)——不能直接相乘得到密钥。

    3.3 中间人攻击（MiM）★¶

    1. Trudy 截获 Alice 的 \(g^a\)，自己选 t，把 \(g^t\) 发给 Bob。
    2. Trudy 截获 Bob 的 \(g^b\)，把 \(g^t\) 发给 Alice。
    3. Alice 算 \(K_AT = g^{at}\)；Bob 算 \(K_BT = g^{bt}\)；Trudy 两个都能算。
    4. 之后 Trudy 用 K_AT 与 Alice 通信、用 K_BT 与 Bob 通信，双方毫不知情。

    根源：DH 本身没有认证——Alice 无法确认 \(g^t\) 来自 Bob。 防御：用证书/签名/预共享密钥对 DH 的公钥值做认证（如 TLS 的签名密钥交换、Signal 的 X3DH 等）。

    3.4 小例（p=23, g=5, a=6, b=15）¶

    1A = 5⁶ mod 23 = 8
2B = 5¹⁵ mod 23 = 19
3Alice: K = 19⁶ mod 23 = 2
4Bob:   K = 8¹⁵ mod 23 = 2

    4. 数字签名 ★★¶

    4.1 机制¶

    • 签名：\(S = [M]_{\\text{Alice}} = M^d \bmod N\)（用私钥“加密”）。
    • 验证：\(M = S^e \bmod N\)（用公钥“解密”）。
    • 只有 Alice 知道 d，所以只有她能生成 S；任何人可验证。

    4.2 为什么能抗抵赖（non-repudiation）★¶

    MAC 数字签名
    密钥 双方共享 K 签名者独占私钥
    Bob 能否伪造 能（他也知道 K） 不能（没有 d）
    能否向第三方证明 不能 能
    抗抵赖 无 有

    场景：Alice 向 Bob 下单 100 股。 - 用 MAC：股价跌后 Alice 否认；Bob 无法证明不是自己伪造的（他也有 K）。 - 用签名：只有 Alice 有私钥；Bob 可向法官验证签名 → Alice 无法抵赖。 - 前提：私钥未被偷/泄露。

    4.3 先哈希再签名（hash-then-sign）★★¶

    • 直接签大消息：RSA 运算慢，且签名长度 = 消息长度（不现实）。
    • 改为签 h(M)：S = [h(M)]Alice，发送 (M, S)。
    • 验证：计算 h(M)，与 \(S^e\) 比较。
    • 前提：哈希必须抗碰撞；否则攻击者找 M' 使 h(M')=h(M)，就能把 (M,S) 换成 (M',S)。
    • 这解释了为什么 MD5/SHA-1 碰撞被攻破会直接威胁签名安全。

    4.4 签名 vs 加密的“方向”（易错）¶

    • 加密：公钥加密 → 私钥解密。
    • 签名：私钥“加密” → 公钥“解密”。
    • 不要把“用私钥加密消息”当成“给消息保密”——任何人都能用公钥解开，不提供机密性。

    5. PKI 与证书 ★★¶

    5.1 问题¶

    • 收到 (M, S)，怎么知道这把“Alice 的公钥”真属于 Alice？
    • 攻击者可以伪造“Alice 的公钥”，然后用自己的私钥签名。
    • 解决：可信第三方 CA 为“身份 + 公钥”背书。

    5.2 数字证书¶

    • 内容：用户名字、公钥、有效期、签发者等。
    • 由 CA 用CA 私钥签名。
    • 验证：用 CA 公钥验证证书签名 → 信任证书中的公钥。
    • 常见格式：X.509。

    X.509 主要字段（能列 5 个即可）：

     1Version
 2Serial Number
 3Signature Algorithm
 4Issuer Name
 5Validity Period
 6Subject Name
 7Subject Public Key
 8Issuer Unique ID
 9Subject Unique ID
10Extensions
11Digital Signature

    5.3 证书生命周期¶

    1生成密钥对 → 签发证书 → 使用 → 到期 / 私钥泄露 → 吊销（CRL）→ 重新认证 / 换钥
    • CRL（Certificate Revocation List）：CA 发布“已吊销证书”列表。
    • 吊销检查是 PKI 的实际难点（CRL 太大、OCSP 隐私/可用性问题）。

    5.4 为什么信任 CA？¶

    • 根 CA 证书预装在 OS/浏览器/应用中，随系统更新。
    • CA 通过现实世界手段核验身份（营业执照、域名控制权、电话回访），不是密码学。
    • 信任是传递的：根 CA → 中间 CA → 站点证书。
    • 风险：CA 被攻破/作恶 → 可签发任意证书（历史上发生过）。

    5.5 三种信任模型¶

    模型 结构 例子
    Monopoly 单一/极少数根 CA 早期浏览器厂商根
    Oligarchy 少数受信 CA（最常见） 现代 TLS 生态
    Anarchy 人人都可以是 CA，靠自证/口碑 PGP web of trust

    6. 哈希函数 ★★¶

    6.1 五个性质（必背）¶

    性质 含义 对抗的攻击
    Compression 任意长度 → 固定 n-bit —
    Efficiency 易计算 —
    One-way（preimage） 给定 y，找不到 x 使 H(x)=y 反推明文/口令
    Weak collision（second preimage） 给定 x，找不到 y≠x 使 H(y)=H(x) 篡改单条消息
    Strong collision 找不到任意一对 y≠x 使 H(y)=H(x) 伪造任意消息

    6.2 生日问题 ★★¶

    • 预生日问题（weak collision）：找到“和我是同一天生日”的人，需要 253 人。
    • 生日问题（strong collision）：任意两人同生日，只需 23 人。
    • 一般化：N-bit 哈希，约 \(2^{N/2}\) 次尝试即可找到碰撞。
    • 推论：
    • N-bit 哈希的安全强度只有 N/2 bit；
    • 128-bit（MD5）→ 2⁶⁴；160-bit（SHA-1）→ 2⁸⁰；
    • 而 N-bit 对称密钥强度约 N bit。

    6.3 常见算法¶

    算法 输出 状态
    MD5 128 bit 碰撞易构造，已破
    SHA-1 160 bit 2005 年起可破，已不推荐
    SHA-256/384/512 256/384/512 目前安全
    SHA-3 224/256/384/512 不同结构（sponge），安全
    • 结构：Merkle–Damgård：固定压缩函数 + 逐块迭代，上一块输出参与下一块；无密钥，类似分组密码。
    • 雪崩效应：MD5("...dog") 与 MD5("...dog.") 输出完全不同。

    6.4 哈希的巧用¶

    （1）口令存储（第 7 章详述）

    • 存 h(password)；攻击者预计算字典 → 秒破。
    • 加 salt：存 (s, h(password, s))；攻击者必须为每个用户重算。

    （2）哈希链 / 一次性口令

    • 24 次课，秘密 t：
    • 第 1 次课给 H²³(t)；
    • 第 d 次课给 \(H^{24-d}(t)\)；
    • 第 24 次课给 t。
    • 验证：对收到的值再哈希一次，应等于上一次的值。
    • 安全性：由当前值无法推出下一个值（需要求逆）；且每个值只对应一次课，重放会被索引检查拒绝。

    （3）反垃圾邮件 PoW

    • 要求 h(M, R, T) 的前 N 位为 0。
    • 发送方平均试 \(2^N\) 次；接收方只需 1 次验证。
    • N 可调：正常邮件可接受，垃圾邮件成本指数上升。
    • 区块链 PoW 同源。

    6.5 量子计算：Shor ★★¶

    • Shor 算法（1994）可多项式时间分解大整数、求离散对数。
    • 2048-bit 模数：
    • 数域筛法（经典最好）≈ 125-bit 对称密钥强度；
    • Shor ≈ 30-bit 对称密钥强度。
    • 结论：RSA、DH、DSA/ECDSA 都会失效；对称密码 + 长密钥可存活。
    • 对策：post-quantum cryptography（如 NTRU、格密码）——课件只点名 NTRU。

    7. 例题精讲¶

    例 1：RSA 全流程（12 分）¶

    题：p=11，q=3，e=3，M=8。求 N、φ(N)、d、密文 C，并验证解密。

    解： - \(N = 11\times 3 = 33\) - \(\varphi (N) = 10\times 2 = 20\) - e=3，\(3d \equiv 1 \pmod{20}\) → d=7（3×7=21≡1） - \(C = 8^{3} \bmod 33 = 512 \bmod 33 = 17\) - 验证：\(17^{7} \bmod 33\) - \(17^{2} = 289 \equiv 25\) - \(17^{4} = 25^{2} = 625 \equiv 31\) - \(17^{7} = 17^{4}\cdot 17^{2}\cdot 17 = 31\cdot 25\cdot 17 \equiv 16\cdot 17 = 272 \equiv 8\) ✓

    得分点：φ 算对；d 满足 \(ed\equiv 1\)；解密用反复平方而不是硬算。

    例 2：DH 协商（10 分）¶

    题：p=23，g=5，Alice 的 a=6，Bob 的 b=15。求 A、B、共享密钥 K。

    解： - \(A = 5^{6} \bmod 23 = 8\) - \(B = 5^{15} \bmod 23 = 19\) - Alice：\(K = B^a = 19^{6} \bmod 23 = 2\) - Bob：\(K = A^b = 8^{15} \bmod 23 = 2\)

    得分点：双方算出同一个 K；说明安全性依赖离散对数。

    例 3：DH 中间人（10 分）¶

    题：描述 Trudy 如何在不破解离散对数的情况下，让 Alice 和 Bob 分别以为在和对方通信。

    解： 1. Trudy 选 t，截获 \(g^a\) 后把 \(g^t\) 发给 Bob； 2. 截获 \(g^b\) 后把 \(g^t\) 发给 Alice； 3. Alice 得 \(g^{at}\)，Bob 得 \(g^{bt}\)，Trudy 两个都算得出； 4. Trudy 分别用两把密钥解密/转发，双方无感知。

    防御：对 DH 的交换值做认证（证书/签名/预共享密钥）。

    例 4：生日攻击（8 分）¶

    题：某系统用 128-bit 哈希做完整性校验，攻击者伪造第二原像需要多少次？找任意碰撞需要多少次？

    解： - 第二原像（给定 x 找 y）：约 2¹²⁸； - 任意碰撞（生日）：约 2⁶⁴； - 因此 128-bit 哈希的“抗碰撞强度”只有 64 bit，已不够；应至少 256-bit。

    例 5：哈希链（8 分）¶

    题：24 次课，秘密 t，第 1 次课发送 H²³(t)。第 5 次课应发送什么？验证者如何验证？

    解： - 第 d 次课发送 \(H^{24-d}(t)\)；d=5 → H¹⁹(t)。 - 验证：对上一位的值再哈希一次，应等于第 4 次课收到的值（H(H¹⁹)=H²⁰）。 - 攻击者拿到 H¹⁹(t) 无法推出 H¹⁸(t)（需逆哈希），所以不能提前伪造下一次。

    例 6：为什么 RSA 要填充（6 分）¶

    题：textbook RSA 直接用 \(C=M^e\) 有什么问题？

    解： - 确定性：相同 M 产生相同 C，可字典/重放； - 可延展：\(C_{1}\cdot C_{2} = (M_{1}M2)^e\)； - 签名可伪造：\(S(M_{1})\cdot S(M_{2}) = S(M_{1}M2)\)。 - 解决：加密用 OAEP 等随机填充；签名用 hash + PSS/PKCS#1 v1.5。

    8. 易错点（考场最易丢分）¶

    错误 正确
    RSA 私钥是 (N,d)，公钥是 (N,e) 对；但 p、q、φ(N) 必须保密/销毁
    签名 = 用私钥加密，所以也保密 错；任何人可用公钥解开，不提供机密性
    签名直接签消息，不用哈希 大消息不可行；且 textbook RSA 签名可延展；必须 hash-then-sign
    MAC 能抗抵赖 不能；双方共享密钥
    DH 能加密数据 DH 只协商密钥，不加密/签名
    DH 的 \(g^a\cdot g^b\) 就是共享密钥 错；是 \(g^{a+b}\)，共享密钥是 \(g^{ab}\)
    证书里只有公钥 还有身份、有效期、签发者、签名等
    根 CA 可信是因为密码学 是因为预装 + 现实身份核验；密码学只保证签名完整性
    N-bit 哈希 = N-bit 安全 抗碰撞只有 N/2 bit
    Shor 会破 AES Shor 破 RSA/DH；AES 只怕 Grover（强度减半）
    两个大素数相乘难分解，所以 RSA 一定安全 目前没有比分解更快的通用攻击，但“RSA 难 ⇔ 分解难”未被证明

    9. 自测（先做，再看答案）¶

    1. 陷门单向函数的“单向”和“陷门”各指什么？举一个例子。
    2. 写出 RSA 密钥生成、加密、解密；为什么分解 N 就能破 RSA？
    3. 为什么 RSA 要“每步取模 + 反复平方”？2048-bit RSA 最多加密多少字节？
    4. 什么是混合加密？为什么实际系统不直接用 RSA 加密数据？
    5. 写出 DH 的协议流程；攻击者看到 \(g^a\)、\(g^b\) 为什么不能直接得到 \(g^{ab}\)？
    6. DH 的中间人攻击如何发生？如何防御？
    7. 数字签名为什么能抗抵赖，而 MAC 不能？
    8. 为什么签名要先哈希？如果哈希可碰撞会怎样？
    9. 证书包含哪些字段？CA 的签名如何验证？根 CA 为什么可信？
    10. 哈希的五个性质是什么？生日攻击为什么是 \(2^{N/2}\)？
    11. 哈希链如何实现一次性口令？为什么攻击者不能提前算出下一次的值？
    12. Shor 算法对 RSA/DH 意味着什么？对称密码为什么不受同样影响？

    答案¶

    1. 正向易算、反向难算；掌握陷门（私钥）后反向易算。例：N=pq 易算，分解 N 难，p、q 是陷门。
    2. 选 \(p,q\)；\(N=pq\)；\(\varphi=(p-1)(q-1)\)；选 \(e\) 与 \(\varphi\) 互素；求 \(d\) 使 \(ed\equiv 1 \pmod{\varphi}\)；公钥 \((N,e)\)，私钥 \(d\)。加密 \(C=M^e\)，解密 \(M=C^d\)。分解 \(N\) 得 \(p,q\) → 算 \(\varphi\) → 由 \(e\) 求 \(d\)。
    3. 直接算 \(M^e\) 会产生巨大整数；每步取模保持数值 \(<N^2\)，反复平方把乘法次数降到 \(O(\log e)\)。2048-bit → 256 字节，填充后约 245 字节。
    4. 公钥只加密/封装一个对称密钥，数据用 AES 加密。RSA 慢、消息长度受限、密文膨胀；不适合传大量数据。
    5. Alice 发 \(g^a\)，Bob 发 \(g^b\)；双方算 \(g^{ab}\)。攻击者只有 \(g^a\)、\(g^b\)，相乘得 \(g^{a+b}\)，求 \(g^{ab}\) 需要解 CDH/离散对数。
    6. Trudy 分别与双方用 \(g^t\) 协商，持有两把密钥并转发。防御：认证 DH（证书/签名/预共享密钥）。
    7. 签名私钥只有 Alice 有，Bob 无法伪造，可向第三方验证；MAC 的 K 双方都有，Bob 也能生成。
    8. 大消息直接签名慢且签名过长；哈希把消息压成定长指纹。若哈希可碰撞，攻击者可把 (M,S) 换成 (M',S) 而验证仍通过。
    9. 版本、序列号、签名算法、签发者、有效期、主体、主体公钥、扩展、签名等。用 CA 公钥验签。根 CA 预装在系统/浏览器，身份靠现实核验。
    10. 压缩、效率、单向、弱碰撞、强碰撞。生日悖论：比较所有配对，约 \(\sqrt{2^N}=2^{N/2}\) 次即可期望碰撞。
    11. 第 d 次给 \(H^{24-d}(t)\)；验证者对当前值再哈希一次与上一次比对。由 \(H^k(t)\) 求 \(H^{k-1}(t)\) 需要逆哈希。
    12. Shor 可多项式时间分解/求离散对数 → RSA、DH、ECDSA 失效；对称密码只受 Grover 平方根加速，密钥翻倍即可。
