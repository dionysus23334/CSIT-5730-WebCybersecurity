    第 2 章 · 对称密码 · 复习资料¶

    对应课件：w2/Symmetric-Key-Crypto.pdf

    建议用时：第一遍 90 分钟 + 例题 40 分钟 + 自测 30 分钟

    配套：知识大纲 §2.3

    本章权重：密码学计算与机制题的主战场。DES/AES 参数、Feistel 公式、三种模式、MAC、Grover 几乎必考其一。

    0. 本章主线（先记住这三句）¶

    1. 流密码用短密钥“拉长”成伪随机密钥流，本质是模拟 OTP；分组密码用轮函数迭代处理固定大小的块，本质是电子码本。
    2. 分组密码的安全性来自非线性 S-box；DES 靠 8 个 S-box，AES 靠 ByteSub + MixColumn。
    3. 加密只保机密性，不保完整性；多块数据必须靠模式，完整性必须靠 MAC；量子计算只把对称密钥强度“减半”（Grover）。

    本章常见考法

    题型 典型问法 备考动作
    参数填空 DES/AES/3DES/TEA 的分组、密钥、轮数 背 §7 速记表
    机制推演 写 Feistel 一轮、A5/1 一步、CBC/CTR 加密式 会推公式，不只背结论
    模式比较 ECB/CBC/CTR 的优缺点、适用场景 用“相同明文块是否同密文”串起来
    计算 2DES 中间相遇、Grover、MAC 开销 记住 \(2^{57}\)、\(2^{n/2}\)、1.5×
    设计题 为什么 3DES 用 EDE？为什么 MAC 用不同密钥？ 答“向后兼容/避免 MITM/避免密钥复用”

    1. 流密码（stream cipher）¶

    1.1 定位¶

    • 密钥较短（如 128 bit），但通过算法拉伸成与消息等长的密钥流（keystream）。
    • 加密：\(C_i = P_i \oplus KS_i\)；解密同理。用法与 OTP 完全一样。
    • 优点：硬件实现极高效、内存小、适合语音/嵌入式。
    • 缺点：软件实现慢；现代 CPU 上分组密码（尤其 AES-NI）更快。
    • 代表：A5/1（GSM）、RC4。

    1.2 A5/1（硬件流密码）★¶

    结构

    寄存器 长度 步进抽头 说明
    X 19 bit \(t = x_{13} \oplus x_{16} \oplus x_{17} \oplus x_{18}\) 右移，新位进 x0
    Y 22 bit \(t = y_{20} \oplus y_{21}\) 右移，新位进 y0
    Z 23 bit \(t = z_{7} \oplus z_{20} \oplus z_{21} \oplus z_{22}\) 右移，新位进 z0

    每一步

    1. 取钟控位：\(m = \mathrm{maj}(x_8, y_{10}, z_{10})\)（三取二）。
    2. 若 \(x_8 = m\)，X 步进；若 \(y_{10} = m\)，Y 步进；若 \(z_{10} = m\)，Z 步进（可能两个或三个同时步进）。
    3. 输出密钥流位：\(x_{18} \oplus y_{21} \oplus z_{22}\)。

    majority 例子：\(\mathrm{maj}(0,0,1)=0\)、\(\mathrm{maj}(1,1,0)=1\)、\(\mathrm{maj}(1,0,1)=1\)。

    课件例子：若 \(m = \mathrm{maj}(1,0,1) = 1\)，则 X 步进、Y 不步进、Z 步进；输出位 = 三个寄存器最右位的 XOR（该例为 1）。

    设计取舍：移位寄存器在硬件中极省资源；但软件实现逐位操作很慢。GSM 用它是因为当年的硬件约束。

    注意：A5/1 本身有已知攻击（课件未展开），不要把它当“安全”的代名词；考试若问“为什么现在少用”，答“软件效率 + 已知弱点”。

    1.3 RC4（软件流密码）★¶

    核心：一个 256 字节的置换表 S，随密钥“自修改”；每步输出 1 字节。

    KSA（密钥调度，初始化）

    1for i = 0..255:
2    S[i] = i
3    K[i] = key[i mod N]      # N = 密钥字节数，任意长度
4j = 0
5for i = 0..255:
6    j = (j + S[i] + K[i]) mod 256
7    swap(S[i], S[j])
8i = j = 0

    PRGA（伪随机数生成）

    1i = (i + 1) mod 256
2j = (j + S[i]) mod 256
3swap(S[i], S[j])
4t = (S[i] + S[j]) mod 256
5keystreamByte = S[t]
    • 每步 1 字节（A5/1 每步 1 bit）。
    • 必须丢弃前 256 字节：否则初始输出有偏差，存在攻击（课件明确）。
    • 命名坑：RC5 是分组密码，不是 RC4 的升级版。

    2. 分组密码（block cipher）¶

    2.1 Feistel 结构 ★★¶

    Feistel 不是某个具体算法，而是一个框架：DES、Blowfish、RC5、TEA、Twofish 都是其变体或相关结构。

    加密（P = (L0, R0)）

    \[ \begin{aligned} L_{i+1} &= R_i \\ R_{i+1} &= L_i \oplus F(R_i, K_i),\quad i = 0,\dots,n \\ C &= (R_{n+1}, L_{n+1}) \end{aligned} \]

    （最后左右交换）

    解密（从 \(C = (R_{n+1}, L_{n+1})\) 出发，子密钥逆序）

    \[ \begin{aligned} R_{i-1} &= L_i \\ L_{i-1} &= R_i \oplus F(L_i, K_{i-1}) \\ P &= (L_0, R_0) \end{aligned} \]

    两个必须理解的点

    1. 解密对任意 F 都成立：每轮都是可逆的线性/异或操作，F 不需要可逆。
    2. 安全性只对特定 F 成立：若 \(F = 0\)，每轮只是交换左右，两轮就还原，完全不安全。

    一轮小例：\(L_0=0110\)，\(R_0=1001\)，\(K=1111\)，\(F(R,K)=R\oplus K\)。

    • \(L_1 = R_0 = 1001\)
    • \(R_{1} = L_{0} \oplus F(R_{0},K) = 0110 \oplus (1001\oplus 1111) = 0110 \oplus 0110 = 0000\)
    • \(C = (R_1, L_1) = (0000, 1001)\)

    解密验证：\(R_0 = L_1 = 1001\)；\(L_{0} = R_{1} \oplus F(L_{1},K) = 0000 \oplus (1001\oplus 1111) = 0110\)。还原成功。

    2.2 DES ★★¶

    参数 值
    分组长度 64 bit
    密钥长度 56 bit（64 bit 中含 8 个校验位）
    轮数 16
    每轮子密钥 48 bit
    结构 Feistel
    安全核心 8 个 S-box（6 bit → 4 bit）

    一轮流程（背顺序）

    1R (32 bit)
2  → 扩展置换 E → 48 bit
3  → 与子密钥 Ki (48 bit) XOR
4  → 8 个 S-box（每个 6→4）→ 32 bit
5  → P-box 置换 → 32 bit
6  → 与 L XOR
7  → 左右交换

    DES 一轮：32-bit R 先扩展成 48 bit，与 48-bit 子密钥异或，过 8 个 S-box 回到 32 bit，再经 P-box 与 L 异或；右侧是子密钥生成。

    • 扩展置换 E：32 → 48 bit，通过重复边缘位把数据分成 8 组、每组 6 bit。
    • S-box：唯一的非线性部件。输入 6 bit：首尾 2 bit 选行（0–3），中间 4 bit 选列（0–15），输出 4 bit。DES 的 S-box 经过精心设计以抵抗差分/线性分析 → DES 的安全性主要来自这里。
    • P-box：对 32 bit 输出再做置换，提供扩散。
    • 子密钥生成：56 bit 密钥分两半各 28 bit，每轮循环左移，再压缩选 48 bit。
    • 初始置换 IP / 末置换 FP：不提供任何安全性，只是历史设计；软件实现常直接省略。

    扩展置换 E 的 8 组输出（输入位编号 0–31）

    组 6 bit 输出（输入位号）
    1 31, 0, 1, 2, 3, 4
    2 3, 4, 5, 6, 7, 8
    3 7, 8, 9, 10, 11, 12
    4 11, 12, 13, 14, 15, 16
    5 15, 16, 17, 18, 19, 20
    6 19, 20, 21, 22, 23, 24
    7 23, 24, 25, 26, 27, 28
    8 27, 28, 29, 30, 31, 0

    相邻两组共享 2 个边缘位，所以 32 bit 被“拉”成 48 bit；这不是随意的重复，而是为了让每个 S-box 的输入都跨过原始 4-bit 边界，增加扩散。

    P-box（32 → 32）

    输出位 输入位号
    0–15 15, 6, 19, 20, 28, 11, 27, 16, 0, 14, 22, 25, 4, 17, 30, 9
    16–31 1, 7, 23, 13, 31, 26, 2, 8, 18, 12, 29, 5, 21, 10, 3, 24

    P-box 把每个 S-box 的输出位重新打散到下一轮的不同 S-box，避免某一组长期影响同一组。

    解密：DES 的解密使用同一套 Feistel 网络，只是 16 个子密钥按 \(K_{16},K_{15},\dots,K_1\) 逆序使用；IP/FP 互为逆置换。

    破解历史（记数字）

    • 1998 年 EFF 的 DES Cracker：成本 < $250,000，< 3 天破解。
    • 1999 年 distributed.net：利用大量机器空闲时间，22 小时 15 分。
    • 结论：56-bit 密钥太短，穷举可行；DES 已不安全。

    2.3 3DES（Triple DES）★¶

    结构：\(C = E(D(E(P,K_1),K_2),K_1)\)，即 EDE，两把密钥，有效强度 112 bit。

    为什么用 EDE 而不是 EEE？

    • 向后兼容：当 \(K_1 = K_2 = K\) 时，\(E(D(E(P,K),K),K) = E(P,K)\)，退化为普通 DES。
    • 这样老系统升级时可以用单密钥模式互操作。

    为什么不用双重加密 \(E(E(P,K_1),K_2)\)？

    • 双重加密名义强度 112 bit，但存在中间相遇攻击（meet-in-the-middle）：
    • 对每个 K1 计算 \(E_{K_{1}}(P)\) 并存储（约 \(2^{56}\)）；
    • 对每个 K2 计算 \(D_{K_{2}}(C)\) 并查找匹配（约 \(2^{56}\)）；
    • 总时间/空间约 \(2^{56}\)，合并约 \(2^{57}\)，而不是 \(2^{112}\)。
    • 3DES 的 EDE 结构（外层 E 用 K1、内层 D 用 K2）不能直接套用这个简单的中间相遇，因此保留约 112-bit 强度。

    ⚠ 易错：课件里的“\(2^{112}\) → \(2^{57}\)”说的是双重加密 2DES；不要把 \(2^{57}\) 当成 3DES 的有效强度。3DES 两密钥版本约 112 bit。

    三密钥 3DES：E(D(E(P,K1),K2),K3)，强度约 168 bit（课件只讲两密钥版本）。

    2.4 AES ★★¶

    参数 值
    分组长度 128 bit（16 字节，4×4 字节矩阵）
    密钥长度 128 / 192 / 256 bit
    轮数 10 / 12 / 14（对应上述密钥）
    结构 不是 Feistel（SPN 型）

    每轮 4 个操作（顺序不能错）

    1. ByteSub（SubBytes）：逐字节查 S-box，唯一非线性层；无不动点（\(S(a) \neq a\)），且需要逆表解密。
    2. ShiftRow（ShiftRows）：第 0 行不移、第 1 行移 1 字节、第 2 行移 2、第 3 行移 3；目的是让各列混合，避免每列被独立加密。
    3. MixColumn（MixColumns）：每列左乘一个可逆矩阵（GF(\(2^{8}\)) 上），实现上是查表；提供列内扩散。
    4. AddRoundKey：与子密钥 XOR（唯一的“密钥注入”步骤）。

    为什么 AES 流行

    • 8-bit / 32-bit CPU 上都高效；代码与内存 footprint 小。
    • 有硬件指令 AES-NI（AESENC / AESDEC），软件也能很快。
    • 雪崩效应：明文 1 bit 变化 → 密文大面积变化。

    课件明确：不要求背 AES 实现细节，但必须能说清四个操作的作用，以及“为什么不是 Feistel”（AES 每轮对整块做代换-置换，而不是只处理一半）。

    2.5 TEA（Tiny Encryption Algorithm）¶

    参数 值
    分组 64 bit
    密钥 128 bit
    轮数 可变，32 轮视为安全
    常数 \(\delta = \texttt{0x9e3779b9}\)（黄金比例）
    特点 弱轮函数 + 多轮；“almost Feistel”（用 +/- 而非纯 XOR）

    弱点：存在等价密钥（4 把不同密钥给出相同密文），有效强度从 \(2^{128}\) 降到约 \(2^{126}\)；还有 X-box 类攻击。课件不要求背实现。

    2.6 线性密码分析（linear cryptanalysis）★¶

    • 分组密码唯一的非线性部件是 S-box；攻击思路是用线性方程近似 S-box。
    • 对给定 S-box，统计输入/输出比特的线性关系成立概率：
    • \(y_1 = x_1\) 以 3/4 概率成立；
    • \(y_{0} = x_{0} \oplus x_{2} \oplus 1\) 以概率 1 成立；
    • \(y_{0} \oplus y_{1} = x_{1} \oplus x_{2}\) 以 3/4 概率成立。
    • 偏差（bias） 越大，近似越好；沿多轮传播后可恢复子密钥。
    • DES 的 S-box 设计使单个输出比特没有好的线性逼近，但输出比特的线性组合仍可被输入线性组合逼近；实践中需要海量明文，并不实用。

    3. 分组模式（modes of operation）¶

    3.1 为什么需要模式¶

    • 分组只有 64/128 bit，消息远大于一块。
    • 每块换新密钥 = OTP 的不现实（密钥分发）。
    • 于是用固定密钥 + 链接/计数器处理多块；部分块（partial block）不在本课范围。

    3.2 ECB（Electronic Codebook）★¶

    \[ \begin{aligned} C_i &= E(P_i, K) \\ P_i &= D(C_i, K) \end{aligned} \]
    • 相同明文块 → 相同密文块。
    • 等价于“每个密钥一本电子码本”。

    问题 1：cut-and-paste

    明文：Eva. pings Bob. Ted. pings Tom.（64-bit 块、8-bit ASCII） - P0=Eva. pin，P1=gs Bob.，P2=Ted. pin，P3=gs Tom. - 密文 C0 C1 C2 C3；攻击者重排为 C0 C3 C2 C1； - 解密得到：Eva. pin + gs Tom. + Ted. pin + gs Bob. = Eva. pings Tom. Ted. pings Bob.

    问题 2：模式泄露

    • 加密一张未压缩图片，仍能看出大块轮廓——因为相同明文块产生相同密文块。
    • 攻击者即使不知道明文，也能知道“哪些块相同”。

    3.3 CBC（Cipher Block Chaining）★¶

    \[ \begin{aligned} C_0 &= E(IV \oplus P_0, K) \\ C_i &= E(C_{i-1} \oplus P_i, K) \\ P_0 &= IV \oplus D(C_0, K) \\ P_i &= C_{i-1} \oplus D(C_i, K) \end{aligned} \]
    • IV 随机，但不需要保密；作用是把相同的 P0 变成不同的 C0。
    • 相同明文块 → 不同密文块（因为链接值不同）。
    • 错误传播有限：若 C1 损坏，P1 变乱、P2 的对应位受影响，但 P3 以后正常。
    • 仍然可 cut-and-paste（整块重排）。
    • 可延展（malleable）：翻转 \(C_{i-1}\) 的某 bit → \(P_i\) 的同一 bit 翻转，\(P_{i-1}\) 变乱。攻击者若知道 \(P_i\) 的结构（如金额），可定向篡改 → 再次说明加密不保完整性。

    考点：CBC 的 IV 要不要保密？——不要；要不要随机/不可预测？——要。

    3.4 CTR（Counter）★¶

    \[ \begin{aligned} C_i &= P_i \oplus E(IV + i, K) \\ P_i &= C_i \oplus E(IV + i, K) \end{aligned} \]
    • 把分组密码当流密码用；支持随机访问（可直接跳到第 i 块）。
    • 可并行、可预计算。
    • ⚠ IV/nonce 绝不能重用：若同一 E(IV) 加密两条消息，则 \(C_{1}\oplus C_{2} = P_{1}\oplus P_{2}\)，等价于两次一密。

    3.5 三种模式对比（背这张表）¶

    维度 ECB CBC CTR
    相同明文块 相同密文 不同密文 不同密文
    并行加密 可 不可（链式） 可
    随机访问 可 不可 可
    错误传播 仅本块 本块 + 下一块部分 仅本块
    需要 IV 无 需要（随机） 需要（唯一，不能重用）
    主要问题 模式泄露、cut-paste 可延展、cut-paste nonce 重用灾难
    典型用途 不推荐 文件/消息加密 磁盘/网络/随机访问

    3.6 完整性：MAC ★★¶

    为什么需要 MAC

    • 加密只防“读”，不防“改”：OTP 可翻转、ECB 可重排、CBC 可比特翻转。
    • 完整性 = 检测未授权的写。

    MAC = CBC residue

    \[ \begin{aligned} C_0 &= E(IV \oplus P_0, K) \\ C_1 &= E(C_0 \oplus P_1, K) \\ &\vdots \\ C_{N-1} &= E(C_{N-2} \oplus P_{N-1}, K) = \mathrm{MAC} \end{aligned} \]
    • 发送 \((IV, P_0\\dots P_{N-1}, MAC)\)；接收方用同一 K 重算，比对 MAC。
    • 为什么能检测篡改：改动任一 P_i 会沿链传播到最终 MAC；没有 K 无法伪造新 MAC。

    为什么加密和 MAC 要用不同密钥

    • 若用同一把密钥，把最后密文块（MAC）再发一遍不增加任何安全性；
    • 不同密钥（即使相关）可以工作，但代价约 2 倍加密；优化可到约 1.5 倍；
    • AE（authenticated encryption） 是“一次运算同时提供 C + I”的研究方向。

    MAC vs 数字签名：MAC 双方共享密钥，Bob 也能伪造 → 不能抗抵赖；签名用私钥，只有签名者能生成 → 可抗抵赖（第 3 章）。

    4. 量子计算与对称密码¶

    • 量子比特可处于 0/1 叠加；N 个 qubit 有 \(2^N\) 个振幅。
    • Grover 算法：对穷举搜索做平方根加速。
    • 经典：n-bit 密钥，工作因子约 2ⁿ；
    • Grover：约 \(2^{n/2}\)。
    • 对 AES-128：Grover 后约 \(2^{64}\) → 不再够；对策是 AES-256（Grover 后约 \(2^{128}\)）。
    • 结论：量子对对称密码不是致命威胁，密钥长度翻倍即可；真正危险的是 RSA/DH（Shor，第 3 章）。

    5. 例题精讲¶

    例 1：Feistel 一轮（8 分）¶

    题：L0=0110，R0=1001，K=1111，F(R,K)=R⊕K。求一轮后的 (L1,R1) 与密文 C。

    解： - \(L_1 = R_0 = 1001\) - \(R_{1} = L_{0} \oplus F(R_{0},K) = 0110 \oplus (1001\oplus 1111) = 0110 \oplus 0110 = 0000\) - \(C = (R_1, L_1) = (0000, 1001)\)

    得分点：公式写对；最后左右交换（最容易漏）。

    例 2：2DES 中间相遇（10 分）¶

    题：双重加密 \(C = E(E(P,K_1),K_2)\)，密钥各 56 bit。说明 MITM 如何把 \(2^{112}\) 降到约 \(2^{57}\)。

    解： 1. 对全部 \(2^{56}\) 个 K1，计算 \(X = E(P,K_1)\)，存入表（按 X 排序/哈希）。 2. 对全部 \(2^{56}\) 个 K2，计算 \(Y = D(C,K_2)\)。 3. 找 \(X = Y\) 的匹配 → 候选 (K1,K2)，再用第二组明文/密文验证。 4. 时间 ≈ \(2^{56}\) + \(2^{56}\) = \(2^{57}\)，空间 ≈ \(2^{56}\)。

    结论：双重加密没有 112-bit 强度；3DES 用 EDE 避免这种直接分解。

    例 3：ECB cut-and-paste（8 分）¶

    题：明文由 4 个 64-bit 块组成：Eva. pin | gs Bob. | Ted. pin | gs Tom.，密文为 C0 C1 C2 C3。如何让解密结果变成 Eva. pings Tom. Ted. pings Bob.？

    解：发送 C0 C3 C2 C1。 - 解密：P0=Eva. pin，P3=gs Tom.，P2=Ted. pin，P1=gs Bob. - 拼接：Eva. pings Tom. Ted. pings Bob.

    得分点：说明 ECB 每块独立，所以块可任意重排。

    例 4：CBC 比特翻转（10 分）¶

    题：CBC 加密中，攻击者翻转 C1 的第 3 个 bit，解密后哪些明文块受影响？攻击者能否定向修改 P2？

    解： - P1 由 D(C1) 计算 → C1 变则 P1 整块变乱（不可预测）； - P2 = C1 ⊕ D(C2) → C1 的第 3 bit 翻转会使 P2 的第 3 bit 精确翻转； - 因此攻击者无法控制 P1，但可以定向翻转 P2 的任意 bit（只要知道 P2 的结构）。 - 结论：CBC 加密不提供完整性；必须加 MAC/AE。

    例 5：Grover（6 分）¶

    题：AES-128 在量子计算下还剩多少安全强度？怎么办？

    解： - Grover 把穷举从 \(2^{128}\) 降到约 \(2^{64}\)； - \(2^{64}\) 对现代算力已不够 → 改用 AES-256，Grover 后约 \(2^{128}\)； - 代价只是“稍慢”，可接受。

    6. 易错点（考场最易丢分）¶

    错误 正确
    3DES 两密钥强度 = 168 bit 两密钥约 112 bit；三密钥才约 168
    “\(2^{57}\) 是 3DES 的强度” \(2^{57}\) 是双重加密 2DES 的 MITM 代价；3DES EDE 约 112 bit
    Feistel 解密需要 F 可逆 不需要；Feistel 对任意 F 都可逆，但安全性依赖 F
    AES 是 Feistel 不是；AES 是 SPN（代换-置换网络）
    3DES 的 EDE 是为了“更难破解” 首要目的是向后兼容单密钥 DES；同时避免 2DES 的 MITM
    CBC 的 IV 必须保密 IV 不需要保密，但需要随机/不可预测
    CTR 的 nonce 可以重复 绝对不能；重用等价于两次一密
    加密能顺带保证完整性 不能；必须 MAC/签名/AE
    MAC 能抗抵赖 不能；双方共享密钥，Bob 也能伪造
    Grover 让 AES 失效 只是强度减半；AES-256 可恢复 128-bit 安全
    RC5 是 RC4 的升级 RC5 是分组密码，与 RC4 无关

    7. 自测（先做，再看答案）¶

    1. 流密码与分组密码的本质区别？各举两个算法。
    2. A5/1 的 majority clocking 如何工作？输出位如何计算？
    3. RC4 的 KSA 与 PRGA 各做什么？为什么必须丢弃前 256 字节？
    4. 写出 Feistel 的加密与解密公式；为什么“任意 F 都能解密，但不是任意 F 都安全”？
    5. DES 的分组、密钥、轮数、子密钥长度、S-box 规格各是多少？安全性来自哪里？
    6. 3DES 为什么用 EDE？为什么不用 \(E(E(P,K_1),K_2)\)？
    7. AES 的四个轮操作及各自作用？为什么说它不是 Feistel？
    8. ECB 的两个致命问题？CBC 如何解决？CBC 还剩下什么问题？
    9. CTR 的 nonce 为什么绝不能重用？给出攻击者能直接计算的量。
    10. MAC 为什么能检测篡改？为什么加密与 MAC 要用不同密钥？
    11. Grover 对 AES-128/256 分别意味着什么？

    答案¶

    1. 流密码按 bit/byte 生成密钥流（A5/1、RC4）；分组密码按固定块迭代轮函数（DES、AES）。
    2. \(m = \mathrm{maj}(x_8,y_{10},z_{10})\)；钟控位等于 m 的寄存器才步进；输出 \(x_{18}\oplus y_{21}\oplus z_{22}\)。
    3. KSA 用密钥打乱 256 字节置换表；PRGA 每步交换并输出 1 字节；前 256 字节有统计偏差，保留会被利用。
    4. \(L_{i+1}=R_i\)，\(R_{i+1}=L_i\oplus F(R_i,K_i)\)，\(C=(R_{n+1},L_{n+1})\)；解密反向、子密钥逆序。因为每轮可逆，F 不必可逆；但 \(F=0\) 时只剩交换，毫无混淆。
    5. 64/56/16/48/8 个 S-box（6→4）。安全性主要来自 S-box 的非线性。
    6. EDE 在 K1=K2 时退化为 DES（向后兼容）；\(E(E(P,K_1),K_2)\) 会被 MITM 从 \(2^{112}\) 降到约 \(2^{57}\)。
    7. ByteSub（非线性）、ShiftRow（行扩散）、MixColumn（列扩散）、AddRoundKey（密钥注入）。AES 每轮处理整个 128-bit 状态，不是只处理一半。
    8. 相同明文块产生相同密文 → 模式泄露；块可重排 → cut-and-paste。CBC 用链接和随机 IV 解决“相同块”；但仍可整块重排和比特翻转。
    9. \(C_{1}\oplus C_{2} = P_{1}\oplus P_{2}\)；同一 E(IV) 被用两次，两条密文异或即两条明文异或。
    10. 改任一明文块会沿 CBC 链传播到最终 MAC；没有 K 无法伪造。同一密钥下 MAC 与密文可互相“借用”，且发送两次不增加安全；不同密钥隔离用途。
    11. AES-128 → 约 \(2^{64}\)（不够）；AES-256 → 约 \(2^{128}\)（够）；代价是稍慢。
