    第 7 章 · 认证与网络安全 · 复习资料¶

    对应课件：w7/authentication.pdf、w7/network-security.pdf

    建议用时：第一遍 90 分钟 + 例题 30 分钟 + 自测 30 分钟

    配套：知识大纲 §2.11、§2.12

    本章权重：认证因子、口令熵/加盐、生物特征错误率是简答/计算题；网络部分几乎全是“分层 + 协议 + 攻击”的对应关系，适合出综合题。

    0. 本章主线（先记住这三句）¶

    1. 访问控制 = 认证（你是谁）+ 授权（你能做什么）；认证靠“你知道/你拥有/你是什么”。
    2. 口令的弱点是用户选择（不是长度本身）；哈希 + salt 让离线字典攻击从“一次预计算”变成“每个用户重算”。生物特征难伪造，但不可撤销。
    3. 网络是分层、分组交换的协议栈；每层有自己的地址与协议，也有自己的攻击面：应用层欺骗、传输层 DoS、网络层 IP（Internet Protocol，网际协议）/NAT、链路层 ARP 欺骗。

    本章常见考法

    题型 典型问法 备考动作
    概念辨析 认证 vs 授权；三种因子 每个因子举 3 个例子
    计算 口令熵、salt 后的攻击量、EER 会算 log2、会比较
    协议 TCP 三次握手、DNS 解析、NAT 画时序/表格
    攻击 SYN flood、DNS 投毒、ARP 投毒 按“层 + 根因 + 防御”记
    设计 如何设计安全登录/防重放 组合口令 + salt + 2FA + 限速

    1. 认证（authentication）¶

    1.1 访问控制的两部分 ★¶

    概念 问题 例子
    Authentication 认证 你是不是你说的那个人？ 登录、指纹解锁、证书校验
    Authorization 授权 你被允许做这件事吗？ 普通用户不能删库；RBAC/ACL
    • 认证可以发生在“人→机”，也可以“机→机”（如 TLS 证书）。
    • 先认证、后授权；认证失败就不该进入授权判断。

    1.2 三种认证因子 ★★¶

    因子 含义 例子 优点 缺点
    Something you know 你知道的 口令、PIN、生日、母亲婚前姓、宠物名 免费、易重置 弱、可猜、可泄露、可共享
    Something you have 你拥有的 智能卡、ATM 卡、令牌、手机、MAC 地址 需物理持有，难远程复制 会丢、需发放/管理
    Something you are 你是什么 指纹、人脸、声纹、签名、步态 难伪造、无需记忆 不可撤销、有错误率、采集需配合

    2FA（双因子）：三类中任取两类。 - 例：信用卡 + 签名；ATM 卡 + PIN；口令 + 手机验证码。

    1.3 口令（passwords）★★¶

    为什么口令流行¶

    • 成本：免费；
    • 便利：重置口令比“重新发一个拇指”容易；
    • 但课件引用：“口令是当今安全工程师面临的最大实践问题之一。”

    密钥 vs 口令（关键计算）¶

    密钥 口令
    生成方式 随机 人选
    64-bit 密钥 2⁶⁴ 个，攻击者约试 2⁶³ —
    8 字符、每字符 256 种 理论 256⁸ = 2⁶⁴ 但用户不随机选 → 实际远小于 2⁶³
    攻击方式 穷举 字典攻击
    • 字典攻击：只尝试最可能的候选（字典词、变形、常见组合）。
    • 例：8 个小写字母 → 26⁸ ≈ 2³⁷·⁶；8 个可打印字符（95 种）→ 95⁸ ≈ 2⁵²·⁶。

    好坏口令与 passphrase¶

    坏口令：frank、Fido、Password、incorrect、Pikachu、88195277、AustinStamp。 好口令：jfIej,43j-EmmL+y、09864376537263、0nceuP0nAt1m8、P0kem0n。

    Passphrase（口令短语）：

    • 长度 10–30 个字母，暴力破解难；
    • 若选得好，不会出现在短语/名言字典里；
    • 结构上比随机串好记。

    课件实验（三组用户）

    组 要求 被破解比例 记忆难度
    A ≥6 字符，至少 1 个非字母 约 30% 一般
    B 基于 passphrase 约 10% 容易
    C 8 个随机字符 约 10% 难

    结论：passphrase 在安全性与可记忆性之间更优；“加一个特殊字符”式的复杂度要求效果有限。

    口令攻击面¶

    • 针对某个账户 / 系统内任意账户 / 任意系统账户；
    • DoS：反复输错锁定账户（想想 ATM 吞卡）；
    • 离线：拿到口令哈希文件后字典/暴力攻击；
    • 在线：猜测、撞库（credential stuffing）、钓鱼、社会工程、键盘记录；
    • 错误日志可能包含“近似口令”；默认口令不修改。

    口令存储：哈希 + 盐 ★★¶

    只哈希（不加盐）的问题

    1. 攻击者预计算 h(x)（字典中所有口令）→ 一次预计算，之后比对哈希即可秒破；
    2. 相同口令 → 相同哈希 → 可批量识别。

    加盐（salt）

    1选随机 s；存 (s, y = h(password, s))
    • s 不保密，可以和 y 一起存；
    • 验证：用存储的 s 重新计算 h(输入, s)，与 y 比较；
    • 攻击者必须为每个用户、每个 salt 重新计算，预计算表失效；
    • 代价：离线攻击从 |D| 变成 |D| × 用户数（还要加慢哈希的每次成本）。

    现代实践还会用慢哈希（bcrypt/scrypt/Argon2）增加单次计算成本；课件未展开，答题可提一句。

    其他口令问题¶

    • 口令太多 → 重用 → 一处泄露、处处沦陷；
    • 默认口令不修改；
    • 社会工程；
    • 登录口令 vs ATM PIN 混用；
    • 键盘记录/间谍软件；
    • 破解工具：L0phtCrack/LC4（Windows）、John the Ripper（Unix）；管理员应主动做弱口令审计。

    1.4 生物特征（biometrics）★¶

    理想属性¶

    属性 含义 现实
    Universal 对（几乎）所有人适用 没有一种特征对所有人适用
    Distinguishing 能唯一区分 无法 100% 确定
    Permanent 终身不变 只要长期有效即可
    Collectable 易采集 取决于用户是否配合
    安全、用户友好 — 需权衡

    Enrollment vs Recognition¶

    阶段 要求 风险
    Enrollment 注册 录入数据库；可慢、可重复测量；必须非常精确 注册环节可能是薄弱点（root trust）
    Recognition 识别 必须快速、简单，同时足够准确 误拒/误受

    错误率：fraud vs insult ★★¶

    • Fraud：攻击者被误认成 Alice（冒充者被接受）。
    • Insult：Alice 未被认成 Alice（本人被拒绝）。
    • 两者此消彼长：
    • 阈值高（99% 匹配）→ fraud 低、insult 高；
    • 阈值低（30% 匹配）→ fraud 高、insult 低。
    • EER（Equal Error Rate）：fraud = insult 的阈值点；用于比较不同生物特征，越小越好。

    ⚠ 课件把 fraud 标成 “false negative”、insult 标成 “false positive”，与常规术语相反；按定义描述记：冒充者被接受 = fraud，本人被拒 = insult。

    生物特征不是万无一失¶

    • 可偷拇指、复印指纹/虹膜、3D 打印面具；
    • 可攻破软件/数据库/可信基（TCB）；
    • 无法撤销“被泄露的指纹”——这是与口令最大的区别（口令可改，指纹不能换）。

    1.5 2FA 与“拥有”因子¶

    • 2FA：任意两类因子组合。
    • “拥有”的例子：车钥匙、笔记本（MAC 地址）、口令生成器、ATM 卡、智能卡。
    • 注意：短信验证码属于“拥有手机”，但存在 SIM swap/拦截风险（课件未展开）。

    2. 网络基础与安全¶

    2.1 基本概念 ★¶

    • 网络 = 主机（computer/laptop/server/phone）+ 互联的路由器 mesh；目的是传数据。
    • 分组交换 vs 电路交换：
    • 电话网是电路交换：每次通话建立专用电路，带宽浪费；
    • 数据网是分组交换：数据切成分组、独立传输、无专用电路；带宽效率高，但更复杂。
    • 协议：精确规定通信规则；细节在 RFC（事实上的 Internet 标准）。
    • Stateless vs Stateful：无状态不“记住”，有状态“记住”；许多安全问题与状态有关（如 DoS 针对有状态协议）。

    2.2 五层协议栈 ★★¶

    层 协议例 作用 地址
    Application HTTP、FTP、SMTP、DNS 应用语义 域名/URL
    Transport TCP、UDP 端到端传输 端口（16 bit）
    Network IP、RIP/OSPF/BGP 路由/寻址 IP（32 bit）
    Link Ethernet、PPP、802.11 相邻节点传输 MAC（48 bit）
    Physical — 比特流 —

    分层运行

    • 源端数据沿栈“下行”，每层加头；
    • 路由器只处理到网络层（路由信息在此），再下行转发；
    • 目的端“上行”到应用层。

    封装

    1应用层： (H, X)
2传输层： (H, (H, X))
3网络层： (H, (H, (H, X)))
4链路层： (H, (H, (H, (H, X))))
    • 应用数据在最内层；每层头只被对等层理解。

    2.3 应用层 ★¶

    HTTP

    • 请求/响应；HTTP 是无状态的。
    • 客户端先说，服务器响应（client-server）；P2P 中主机既是 client 又是 server。

    Cookie

    • 服务器首次下发，浏览器保存并在后续请求带回；
    • 服务器用 cookie 数据库“记住”你（购物车、推荐、会话）；
    • 很弱很弱的认证；
    • 隐私问题：单个站点可了解你，多个站点联合可了解更多（追踪）。

    SMTP

    • 发送方 → 收件人邮件服务器；再用 POP3/IMAP/HTTP 取信。
    • 命令人类可读：
    1telnet server 25
2HELO ca.gov
3MAIL FROM: <arnold@ca.gov>
4RCPT TO: <stamp@cs.sjsu.edu>
5DATA
6...
7.
8QUIT
    • ⚔ 伪造发件人：MAIL FROM 可随意写 → 邮件欺骗。
    • 防御：SPF/DKIM/DMARC、认证（课件未展开，属延伸）。

    DNS

    • 域名 → IP（cse.ust.hk → 143.89.41.177）；分布式数据库。
    • 解析：root → TLD（.hk/.org/.edu）→ 子域，递归进行。
    • 全球只有 13 个 root server 集群 → 事实上的单点故障；针对根服务器的攻击发生过，但未持续足够久。
    • ⚔ DNS 缓存投毒：服务器为性能缓存解析结果；若收到并缓存假记录，就把错误 IP 返回给客户端 → 流量被引到攻击者机器。
    • 防御：DNSSEC、随机化查询 ID/端口、0x20 编码（课件未展开）。

    2.4 传输层 ★¶

    • 网络层只提供“尽力而为”的不可靠交付；改进服务由主机（传输层）提供。
    • TCP：可靠、按序、流控、面向连接（先联系再发数据；逻辑连接，非物理连接）。
    • 头部：源/目的端口、序号、确认号、标志位（ACK/SYN/RST…）、窗口、校验和、紧急指针；无选项时 20 字节。
    • 三次握手：
    1Client → Server: SYN
2Server → Client: SYN-ACK
3Client → Server: ACK（可带数据）
    • ⚔ SYN flooding：
    • 服务器收到 SYN 就记住“半开连接” → 消耗资源（backlog）；
    • 大量半开连接 → 内存/表耗尽 → 无法服务正常请求；
    • 根因：TCP 是有状态的。
    • 防御：SYN cookies、限流、防火墙、缩短超时（课件未展开）。
    • UDP：无连接、开销小、不保证可靠/有序。

    2.5 网络层 ★¶

    • IP：尽力而为；每台主机、每个路由器都运行 IP；路由器还跑路由协议（RIP/OSPF/BGP）。
    • IPv4 地址 32 bit，点分十进制（195.72.180.27，每段 0–255）；地址不够用 → 各种扩展技巧；主机 IP 可能变化。
    • Socket = IP + 端口，全球唯一标识一个进程。
    • 端口 16 bit；<1024 为 well-known（HTTP 80、POP3 110）；>1024 动态。
    • NAT：用一个（或少数）公网 IP + 不同端口映射多个内网主机。
    • 优点：扩展地址空间；隐式隐藏内网源地址。
    • 缺点：DoS 仍可行；破坏端到端透明性。
    • 例：内网 192.168.0.12:1025 ↔ 公网 11.0.0.1:4000，NAT 表维护映射。
    • ⚔ Ping flood / Ping of Death：滥用 ICMP echo request/reply；大量 ICMP 淹没受害者；攻击前可能先塞满自己的带宽。

    2.6 链路层 ★¶

    • 在网卡（NIC）中实现；NIC 半自治、基本不受主机控制；同时实现链路层与物理层。
    • MAC 地址：48 bit，全球唯一；用于在同一链路上转发。
    • 类比：IP 像家庭住址，MAC 像身份证号。
    • ARP：已知 IP，求对应 MAC；每台主机有 ARP 表/缓存，自动生成，条目约 20 分钟过期；ARP 无状态。
    • ⚔ ARP 缓存投毒：
    • 攻击者主动发送伪造 ARP reply（“111.111.111.002 的 MAC 是 CC-CC-...”）；
    • 双方缓存被污染 → 流量经过攻击者 → 中间人。
    • 防御：静态 ARP、DAI（动态 ARP 检测）、加密（课件未展开）。

    2.7 按层归纳攻击面 ★¶

    层 攻击 根因 防御方向
    应用 SMTP 伪造 发件人无认证 SPF/DKIM/DMARC
    应用 DNS 投毒 缓存 + 无签名 DNSSEC、随机化
    应用 Cookie 隐私 跨站追踪 隐私策略、隔离
    传输 SYN flood TCP 有状态 SYN cookies、限流
    网络 IP 欺骗、Ping flood 无源认证、ICMP 滥用 入口过滤、限速
    链路 ARP 投毒 ARP 无状态、无认证 静态 ARP、DAI

    3. 例题精讲¶

    例 1：口令熵（8 分）¶

    题：8 字符口令，分别从 26 个小写字母、95 个可打印字符、256 个字节中随机选取，熵各是多少 bit？为什么实际强度远低于此？

    解： - 26⁸：8×log2(26) ≈ 8×4.70 = 37.6 bit - 95⁸：8×log2(95) ≈ 8×6.57 = 52.6 bit - 256⁸：8×8 = 64 bit - 实际用户不随机选，会使用字典词/变形 → 攻击者用字典攻击，实际搜索空间远小于理论值。

    例 2：加盐（8 分）¶

    题：字典大小 10⁸，系统有 10⁴ 个用户。不加盐与加盐（每用户独立 salt）时，攻击者离线破解全部口令各需多少量级？

    解： - 不加盐：预计算 10⁸ 个哈希，所有用户共用 → 10⁸。 - 加盐：每个用户、每个 salt 都要重算 → 10⁸ × 10⁴ = 10¹²。 - 若再加慢哈希（每次 0.1 秒），成本再乘时间因子。

    例 3：EER（8 分）¶

    题：某指纹系统阈值提高后，fraud 降到 1%，insult 升到 10%。解释原因，并说明 EER 的意义。

    解： - 阈值提高 = 更难通过 → 冒充者更难被接受（fraud↓），但合法用户也更容易被拒（insult↑）。 - 两者随阈值此消彼长；EER 是 fraud=insult 的点，用来横向比较不同生物特征/系统（越小越好）。

    例 4：SYN flood（10 分）¶

    题：描述 SYN flood 的过程，为什么根因是“TCP 有状态”？

    解： 1. 攻击者发送大量 SYN（可伪造源 IP）； 2. 服务器为每个 SYN 分配半开连接（backlog 表项）并回 SYN-ACK； 3. 攻击者不回 ACK → 表项被占满； 4. 新合法 SYN 无法入队 → 拒绝服务。 - 根因：服务器必须记住每个半开连接的状态；状态资源有限。 - 防御：SYN cookies（不保存状态，把信息编码进序列号）、限流、缩短超时。

    例 5：DNS 投毒（10 分）¶

    题：攻击者如何让用户访问 www.bank.com 时被导向自己的服务器？

    解： 1. 攻击者向递归 DNS 服务器发送伪造的响应（匹配查询 ID/端口），声称 www.bank.com 的 A 记录是攻击者 IP； 2. 递归服务器把这个假记录缓存（TTL 内）； 3. 之后所有查询该域名的用户都收到假 IP； 4. 用户连接到攻击者服务器（可做钓鱼/中间人）。 - 防御：DNSSEC（签名）、随机化查询 ID/端口、限制缓存。

    例 6：ARP 投毒（10 分）¶

    题：攻击者如何在同一 LAN 内成为 Alice 与网关之间的中间人？

    解： 1. 攻击者向 Alice 发送伪造 ARP reply：“网关 IP 的 MAC 是我的 MAC”； 2. 向网关发送伪造 ARP reply：“Alice IP 的 MAC 是我的 MAC”； 3. 双方 ARP 缓存被污染，流量都发给攻击者； 4. 攻击者转发（或篡改）流量 → 中间人。 - 根因：ARP 无状态、无认证，收到 reply 就更新缓存。 - 防御：静态 ARP、DAI、端口安全。

    例 7：NAT 表（8 分）¶

    题：内网主机 192.168.0.12:1025 访问 12.0.0.1:80，NAT 公网地址 11.0.0.1，映射端口 4000。写出 NAT 前后的源/目的地址。

    解： - 出方向：src=192.168.0.12:1025, dst=12.0.0.1:80 → src=11.0.0.1:4000, dst=12.0.0.1:80； - NAT 表：4000 ↔ 192.168.0.12:1025； - 回方向：src=12.0.0.1:80, dst=11.0.0.1:4000 → src=12.0.0.1:80, dst=192.168.0.12:1025。

    4. 易错点（考场最易丢分）¶

    错误 正确
    认证 = 授权 认证确认身份；授权决定权限
    2FA = 两个口令 必须是两类不同因子（知道/拥有/是）
    口令越长一定越强 用户可预测的选择会毁掉熵；P@ssw0rd! 仍在字典里
    哈希口令就安全 不加盐可预计算/批量比对；需 salt + 慢哈希
    salt 需要保密 salt 不需要保密，只需唯一/随机
    生物特征可以“改密码” 生物特征不可撤销；泄露后无法更换
    fraud = 本人被拒 fraud = 冒充者被接受；insult = 本人被拒（课件标注相反，按定义记）
    TCP 是“真连接” 只是逻辑连接；底层仍是分组
    UDP 不可靠所以没用 DNS、视频、游戏等用 UDP 换取低延迟
    NAT 能防 DoS NAT 不防 DoS；只扩展地址/隐藏源
    ARP 是三层协议 ARP 在链路层/网络层之间，用于 IP→MAC
    DNS 只有 13 台物理服务器 是 13 个 root server 集群（anycast 多实例）
    Cookie 是认证机制 只是状态管理，认证能力很弱

    5. 自测（先做，再看答案）¶

    1. 认证与授权的区别？三种认证因子各举三例。
    2. 为什么 64-bit 随机密钥比 8 字符口令强？口令的熵受什么影响？
    3. 什么是字典攻击？为什么它比穷举有效？
    4. passphrase 相比“复杂口令”有什么优势？课件实验说明了什么？
    5. 不加盐的哈希口令有什么问题？salt 如何解决？salt 要保密吗？
    6. 生物特征的四个理想属性？Enrollment 与 Recognition 的区别？
    7. fraud 与 insult 分别是什么？EER 的意义？
    8. 为什么生物特征“不可撤销”是根本问题？
    9. 画出五层协议栈，各层举两个协议。
    10. 什么是封装？路由器处理到哪一层？
    11. HTTP 为什么需要 Cookie？Cookie 的隐私风险？
    12. SMTP 如何被伪造？DNS 缓存投毒的步骤？
    13. TCP 三次握手？SYN flood 的根因与防御？
    14. socket 由什么组成？NAT 的优点与缺点？
    15. ARP 投毒如何形成中间人？如何缓解？

    答案¶

    1. 认证确认“你是谁”，授权决定“你能做什么”。知道：口令/PIN/生日；拥有：智能卡/令牌/手机；是：指纹/人脸/声纹。
    2. 密钥随机生成，熵满；口令由人选，受字典/模式/重用影响，实际熵远低于长度理论值。
    3. 只尝试最可能的候选（字典词、变形）；因为用户选择有规律，命中率高，远优于 2⁶⁴ 穷举。
    4. 更长、易记、不易被字典命中；实验：passphrase 组破解率 10% 且好记，复杂规则组 30%。
    5. 可预计算、相同口令同哈希、批量破解；salt 使每个用户哈希唯一，攻击者必须逐用户重算；salt 不需保密。
    6. Universal、Distinguishing、Permanent、Collectable（+安全/友好）。Enrollment 是录入（可慢、要精确）；Recognition 是识别（要快、要准）。
    7. fraud：冒充者被接受；insult：本人被拒。EER 是两者相等点，用于比较系统，越小越好。
    8. 口令泄露可改，指纹/虹膜不能换；一旦泄露终身不可用。
    9. 应用（HTTP/SMTP）、传输（TCP/UDP）、网络（IP/BGP）、链路（Ethernet/ARP）、物理。
    10. 每层加头，应用数据在最内层；路由器处理到网络层。
    11. HTTP 无状态，Cookie 用于会话/购物车/推荐；跨站追踪、隐私泄露；认证能力弱。
    12. SMTP 的 MAIL FROM 可任意写；DNS 投毒：伪造响应 → 递归服务器缓存假记录 → 返回错误 IP。
    13. SYN → SYN-ACK → ACK；服务器为半开连接保存状态，表满即拒绝服务；防御：SYN cookies、限流、缩短超时。
    14. IP + 端口；NAT 扩展地址、隐藏内网；但破坏端到端、DoS 仍可行。
    15. 伪造 ARP reply 污染双方缓存，流量经攻击者；防御：静态 ARP、DAI、端口安全。
