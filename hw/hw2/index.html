    作业二复盘 · 逆向与内存安全¶

    题干是脱敏重述，不是作业原文；答案尽量讲人话，不提供可直接抄的 payload。

    仅作复习，别直接交；课程作业与答案版权归教师所有。

    题目 1 · 两种“扫代码”的方式¶

    题目：反汇编有两种常见思路：一种是从头到尾按字节顺次扫（线性），一种是顺着跳转/调用一路跟（递归）。回答三个小问：

    1. 顺着跳转扫，有什么坑？
    2. 这个坑怎么补？
    3. 开发者想让逆向更难受，可以做什么？

    先分清两种扫法

    • 线性扫：从代码段第一个字节开始，一条接一条往下解，像读书从第一行读到最后一页。
    • 递归扫：从入口开始，遇到 jmp/call 就跟着跳过去，只解“真的会执行”的地方。

    (1) 顺着跳转扫的坑¶

    它只能跟直接跳转。遇到间接跳转就麻烦了，比如：

    1jmp eax
2call [ebx+4]

    eax 里到底是什么地址？静态看代码往往算不出来（可能是运行时才填的表、虚函数、回调）。算不出来，就不知道下一步去哪，于是漏掉一部分代码。

    一句话：直接跳转能跟，间接跳转容易跟丢；跟丢的代码就没被反汇编到。

    (2) 怎么补¶

    • 混着用：先用递归扫；对“落在可执行段、但递归没覆盖”的区域，再用线性扫补一遍；
    • 算一算：常量传播、模拟执行，尽量把 eax 这类值推出来；
    • 找入口：用签名/启发式识别函数开头、跳转表；
    • 跑一跑：动态执行/插桩，看实际执行到哪些地址。

    (3) 怎么让逆向更难受¶

    • 代码混淆：控制流平坦化、不透明谓词、指令替换，让代码“看起来不像原来的结构”；
    • 加壳/加密：运行时再解壳；
    • 反汇编干扰：在代码段里嵌数据，让线性扫把数据当指令。

    题目 2 · 恶意样本真的比正常软件多吗¶

    题目：有人说，现在恶意样本的数量已经超过正常软件，签名库都快装不下了。

    1. 这话靠谱吗？
    2. 如果真是这样，签名检测该怎么改？

    (1) 靠谱吗¶

    要看“怎么数”。

    • 按样本/变体数：一个恶意程序可以自动生成大量多态/变形变种，数量很容易爆炸；这种情况下，“恶意样本更多”完全可能。
    • 按独立程序/家族数：结论可能完全不同，没那么多“家族”。
    • 正常软件也有大量版本，但恶意样本的自动化变种成本更低。

    所以，这句话在“按样本计数”的定义下是合理的；不要把它当成某个具体的全球统计结论。

    (2) 签名检测怎么改¶

    传统签名是“列出坏的特征”。坏样本比好样本多时，签名库会爆炸，而且总会有漏网的新变种。

    换个方向：以好软件为中心（allowlist）

    1. 可信哈希白名单：只让已审核的可执行文件跑；
    2. 未知文件隔离：不在白名单 → 沙箱/隔离，而不是“没坏签名就放行”；
    3. 白名单要防篡改：签名、认证更新，别让攻击者改白名单；
    4. 审核流程：新版本先审再加入；
    5. 别把“批准”当“无漏洞”：白名单只说明“这是你批准的程序”，不代表它没有漏洞；仍需行为监控和补丁管理。

    通俗理解：与其记住“所有坏人的脸”，不如只让“名单上的好人”进门；不认识的人先请到小房间，别直接放进办公室。

    题目 3 · printf(name) 的坑¶

    题目：下面这种写法：

    1char name[64];
2scanf("%63s", name);
3printf(name);

    用户输入会直接被当成格式串。回答：

    1. 用户能搞出什么事？
    2. 除了读内存，还能写吗？
    3. 怎么修？

    (1) 用户能搞出什么¶

    printf 的第一个参数是“格式串”，里面 %s、%d、%x 这些占位符会去取后面的参数。但这里只传了 name 一个参数，后面的参数从哪来？——从栈上“顺手拿”。

    如果用户输入：

    1%s%s%s

    printf 就会把栈上的三个值当成“字符串地址”，把那里的内存打出来。结果可能是：

    • 泄露内存（栈上的数据、地址）；
    • 如果某个值不是合法地址，程序崩溃。

    %x 也会把栈上的数据以十六进制打出来。

    (2) 能从读升级到写吗¶

    能，靠 %n。

    %n 不打印东西，而是把“到目前为止已经输出了多少个字节”写到对应参数指向的地址：

    1int val;
2printf("blah %n blah\n", &val);
3// "blah " 是 5 个字节，所以 val = 5

    攻击者控制格式串，也就控制了 printf 从栈上取的“参数”：可以指定目标地址（返回地址、flag、GOT 等），再用输出宽度控制写入的值。于是从“读内存”升级成“任意内存写”，进一步劫持控制流。

    通俗理解：%s 是“把地址上的东西念出来”，%n 是“把数写到地址上”；一个偷看，一个改账本。

    (3) 怎么修¶

    1. 硬编码格式串：printf("%s", name);——name 是数据，不是格式；
    2. 不需要格式化时用 puts(name)/fputs；
    3. 绝不 printf(user_input)；
    4. 禁用 %n；
    5. 开编译器格式串告警（-Wformat-security）、做代码审计。

    核心：把格式串从用户手里拿走。

    题目 4 · 编译器本身被做手脚¶

    题目：一个团队审了编译器源码和账户检查程序源码，都没发现恶意代码。但他们现在用的编译器可执行文件 C0 被污染了，藏了两条规则：

    • 编译“账户检查程序”源码时，往产物里插后门；
    • 编译“编译器”源码时，把这两条规则也插进新编译器。

    他们用 C0 编出 C1，再用 C1 编出账户检查程序 A1。

    1. C1 和 A1 干净吗？
    2. 删掉 C0，用 C1 再编一个 C2，能解决吗？
    3. 如果有一个独立可信的编译器 T，怎么重建？

    (1) C1 和 A1¶

    • C1 有隐藏规则：C0 认出“这是编译器源码”，把两条规则插进 C1；
    • A1 有后门：C1 认出“这是账户检查源码”，把后门插进 A1；
    • 两份源码都干净，但恶意行为通过编译器“遗传”了。

    通俗理解：不是源代码里写了坏东西，而是“翻译官”在翻译时偷偷加了一句；你检查原文，当然看不出来。

    (2) 删 C0、编 C2¶

    不能解决。C1 已经带规则，编编译器源码时会把同样的规则插进 C2；删 C0 只是删掉“第一代”二进制，后代仍然带毒。

    关键：源码干净 ≠ 编出来的二进制干净；源码审计不能证明编译器忠实。

    (3) 用可信 T 重建¶

    1. 在可信环境里，用 T 编译“编译器源码” → 干净的 C_clean；
    2. 用 C_clean（或直接用 T）编译“账户检查源码” → 干净的 A；
    3. 替换所有受影响的二进制，不只是删 C0 或改源码；
    4. 最好用可复现构建/多样化双编译，防止再次被污染。

    关键：换掉“被污染的构建产物”，从可信根重建工具链。

    题目 5 · 三个登录程序（溢出思路）¶

    题目：有三个登录程序，都从命令行拿 username/password，和文件里的 secret 比。目标是用溢出绕过检查，看到登录成功。三个版本分别加了不同防护：

    • login1：没有 canary；
    • login2：固定 canary；
    • login3：用 username 算出来的 canary。

    下面只讲栈布局和思路，不写可直接抄的 payload；实际偏移要自己用调试器/反汇编确认。

    课程还要求 username 以自己的学号开头，且不能使用 password.txt 里的内容；这里不展开。

    login1：连续字段¶

    布局：几个字段在栈上挨着排：

    1entered_name | entered_secret | stored_name | stored_secret

    思路：

    • username 只填 entered_name，长度刚好不越界；
    • password 从 entered_secret 开始写，会越过自己的缓冲区，覆盖后面的 stored_name 和 stored_secret；
    • 程序会在每个字段末尾写终止符；用 filler 把多余字符“顶掉”；
    • 比较时 entered_name == stored_name、entered_secret == stored_secret，于是通过。

    通俗理解：不是破解密码，而是把“标准答案”改成你刚写进去的那份。

    login2：固定 canary¶

    布局：字段和两个标记交错：

    1entered_name | stored_name | tag1 | stored_secret | tag2 | entered_secret
    • tag1、tag2 初始相等；
    • username 要覆盖 stored_name、tag1、stored_secret、tag2，同时让两个 tag 仍然相等；
    • password 只负责填 entered_secret。

    思路：

    • 用 filler + 你选的 username/password 覆盖 stored 字段；
    • 在两个 tag 的位置都放上相同的值（原来的固定值，或同一个非零字节）；
    • 这样 canary 检查通过，比较也通过。

    通俗理解：canary 是“固定暗号”，你只要在正确的位置把暗号原样写回去，它就发现不了。

    login3：动态 canary¶

    布局：tag 在 password 缓冲区的前后都有：

    1expected_tag | entered_secret | boundary_tag | stored_secret | stored_name | entered_name
    • expected_tag 在 password 缓冲区之前，密码溢出碰不到它；
    • boundary_tag 在 entered_secret 之后，会被 password 覆盖；
    • 程序比较 boundary_tag 和 expected_tag；
    • expected_tag 是由 username 的前几位学号数字算出来的，所以不能写死。

    思路：

    1. username 填 entered_name；
    2. password 从 entered_secret 开始，依次覆盖 boundary_tag、stored_secret、stored_name；
    3. 用学号数字按程序里的公式算出 6 字节 tag G；
    4. 在 boundary_tag 对应的偏移放 G，让 boundary_tag == expected_tag；
    5. 在 stored_name 放你的 username，在 stored_secret 放你的 password；
    6. 终止符落在 stored_name 末尾，不要碰到 entered_name。

    通俗理解：动态 canary 不是“不能绕”，而是“暗号每次不一样”；你得先看懂它怎么算，再自己算一个放回去。

    编程题容易踩的坑¶

    坑 说明
    直接抄 payload 偏移随编译器/栈布局变，换环境就废
    username 不带学号 课程要求，直接没分
    用 password.txt 的内容 题目禁止，视为 secret
    忽略终止符 每个字段末尾的 \0 会改变比较
    canary 位置写错 login2 要两个 tag 相等；login3 要放算出来的 G
    文件格式不对 两行：第一行 username，第二行 password

    复盘清单¶

    题 要点
    1 递归怕间接跳转；线性+递归互补；混淆/加壳
    2 按变体计数 → 恶意多；改 allowlist + 隔离未知 + 签名更新
    3 %s 泄露、%n 任意写；printf("%s", name)、禁 %n
    4 C1 带规则、A1 带后门；删 C0 无用；用可信 T 重建并替换二进制
    5 login1 连续字段；login2 固定 tag；login3 动态 tag 要自己算
