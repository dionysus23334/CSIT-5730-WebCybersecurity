## Q1（14 分）线性 vs 递归反汇编

### (a) 递归反汇编的局限（6 分）

- 递归反汇编从入口点出发，沿**直接控制转移**（`jmp`/`call`/`ret`）遍历。
- 遇到**间接跳转**（如 `jmp %eax`、`call [eax]`、虚表调用）时，静态分析往往无法确定目标地址；
- 因此可能**漏掉一部分可达代码**，覆盖率不完整。

**一句话**：直接跳转能跟，间接跳转跟不了。

### (b) 如何缓解（6 分）

- **线性 + 递归结合**：对递归未覆盖、但位于可执行段的区域，用线性扫描补齐；
- 配合**常量传播/模拟执行**解析部分间接跳转；
- 用启发式/签名识别函数入口、跳转表；
- 动态执行/插桩辅助确认可达代码。

### (c) 如何增加逆向难度（2 分）

- **代码混淆**（控制流平坦化、不透明谓词、指令替换）；
- **加壳/加密**（packer）；
- 反汇编干扰（在代码段嵌入数据）。

## Q2（15 分）恶意软件数量与签名检测

### (a) 恶意软件可能比正常软件多吗？（5 分）

**可能**，但取决于“怎么计数”：

- 若按**不同变体/样本**计数：一个恶意软件可轻易生成大量多态/变形变种，数量会爆炸；
- 若按**独立程序/家族**计数：结论可能不同；
- 正常软件也有大量版本，但恶意样本的**自动化变种**成本更低。

**结论**：在“按样本/变体计数”的定义下，恶意软件多于正常软件是合理的；不要把它当成某个具体的全球统计结论。

### (b) 改进的签名检测系统（10 分）

传统签名：列出“坏”的特征 → 坏样本比好样本多时，签名库爆炸。

**改进思路：以好软件为中心（allowlist）**

1. **可信哈希白名单**：只允许已审核的可执行文件哈希运行；
2. **未知文件隔离**：不在白名单 →  quarantine/沙箱，而不是“没有坏签名就放行”；
3. **签名/更新保护**：白名单数据库要认证、签名、防篡改；
4. **审核流程**：新版本先审核再入白名单；
5. **限制**：白名单小、查询快，但“批准”不等于“无漏洞”；仍需行为监控/漏洞管理。

**核心**：从“枚举坏”转为“只允许好”，并安全地处理未知。

## Q3（15 分）`printf(name)` 格式化字符串

### (a) 会出什么问题？（5 分）

```c
char name[64];
scanf("%63s", name);
printf(name);      // 危险
```

- `printf` 把 `name` 当作**格式串**；
- 用户输入 `%s%s%s` → `printf` 认为后面有三个字符串指针参数，从栈上取“参数”；
- 结果：把栈上的值当地址，打印其指向的内存 → **信息泄露**；非法地址 → 崩溃；
- `%x` 也会打印栈上的数据。

**例子**：输入 `%s%s%s` → 泄露栈内存/崩溃。

### (b) 如何从“读”升级到“写”？（5 分）

利用 **`%n`**：

```c
int val;
printf("blah %n blah\n", &val);
// val = 5（已输出 5 个字节）
```

- `%n` 把“到目前为止已输出的字节数”写入对应参数指向的地址；
- 攻击者控制格式串 → 也控制 `printf` 从栈上取的“参数”；
- 因此可以指定**目标地址**（返回地址、flag、GOT 等），并用输出宽度控制写入值；
- 从信息泄露升级为**任意内存写** → 控制流劫持。

### (c) 如何修复？（5 分）

1. **硬编码格式串**：`printf("%s", name);`
2. 不需要格式化时用 `puts(name)`/`fputs`；
3. **绝不** `printf(user_input)`；
4. 禁用 `%n`（编译选项/安全库）；
5. 编译器 `-Wformat-security` 告警、代码审计。

**核心**：把格式串从攻击者控制中拿走。

## Q4（16 分）Trusting Trust：被污染的编译器

**设定**：源码干净；编译器 C0 被污染，含两条规则：

- 编译“账户检查程序”源码 → 插入后门；
- 编译“编译器”源码 → 把这两条规则也插入新编译器。

用 C0 编译编译器源码得到 C1；用 C1 编译账户检查源码得到 A1。

### (a) C1 和 A1 是否含恶意代码？（6 分）

- **C1 含隐藏规则**：C0 识别“编译器源码”，把两条规则插入 C1；
- **A1 含后门**：C1 识别“账户检查源码”，把后门插入 A1；
- 尽管两份源码都干净，**行为通过编译器继承**。

### (b) 删除 C0，用 C1 编译出 C2，能解决吗？（4 分）

- **不能**。C1 已含隐藏规则，编译编译器源码时会把同样的规则插入 C2；
- 删除 C0 只是删掉“第一代”二进制，C1/C2 仍带毒；
- **源码审计不能证明编译器忠实**：源码干净 ≠ 生成的二进制干净。

### (c) 用可信编译器 T 重建（6 分）

假设 T 独立可信、能正确编译：

1. 在可信环境中用 **T** 编译“编译器源码” → 干净的 `C_clean`；
2. 用 `C_clean`（或直接用 T）编译“账户检查源码” → 干净的 A；
3. **替换所有受影响的二进制**（C1/C2/A1 等），而不只是删除 C0 或改源码；
4. 建立可复现构建/引导信任（diverse double-compiling 等）防止再次污染。

**关键**：要换掉“被污染的构建产物”，并从一个可信根重新建立工具链。

## Q5（40 分）缓冲区溢出（login1/2/3）

> 以下为**布局与偏移思路**，不是可直接提交的答案。实际偏移取决于编译器、编译选项、栈布局；官方答案基于给定环境。

### 共同背景

- 程序从命令行读 username/password，与 `password.txt` 中的 secret 比较；
- 目标：让比较通过，看到 `Login successful!`；
- username 必须以**自己的学号**开头；
- 三个程序分别加了：无 canary（login1）、固定 canary（login2）、运行时由 username 计算的 canary（login3）。

### (a) login1（10 分）

**布局**：字段宽度 `N=36`，内存中连续：

```
entered_name[36] | entered_secret[36] | stored_name[36] | stored_secret[36]
```

**思路**：

- username 写 `entered_name`，长度 35（+ 终止符）刚好不越界；
- password 从 `entered_secret` 开始写，可以**越过** `entered_secret`，覆盖后面的 `stored_name` 和 `stored_secret`；
- 程序在每个字段末尾写终止符，丢弃 filler；
- 比较时 `entered_name == stored_name`、`entered_secret == stored_secret`。

**参考结构**：

```
U = 学号 + 填充到 35 字符
P = 任意密码 + 填充到 35 字符
F = 单字符 filler（如 X）

username = U
password = P ∥ F ∥ U ∥ F ∥ P
```

- 长度：username 35，password 107；
- 第二份 U/P 覆盖 stored 的两个数组；
- 终止符/filler 让每个字段的比较仍然相等。

### (b) login2（10 分）

**布局**：`N=40`，字段顺序：

```
entered_name[40] | stored_name[40] | boundary_tag | stored_secret[40] | expected_tag | entered_secret[40]
```

- 两个 tag 初始都为 `Q`（单字节）；
- username 要同时覆盖 `stored_name`、`boundary_tag`、`stored_secret`、`expected_tag`，并保持两个 tag 都是 `Q`；
- password 只需填 `entered_secret`。

**参考结构**：

```
U = 学号 + 填充到 39 字符
P = 任意密码 + 填充到 39 字符
F = filler

username = U ∥ F ∥ U ∥ F ∥ Q ∥ P ∥ F ∥ Q
password = P
```

- 长度：username 122，password 39；
- 第一份 U/P 写入 stored 字段；两个 `Q` 保持 tag 相等；
- 第二份 P 写入 `entered_secret`。

### (c) login3（20 分）

**布局**：`N=48`，tag 长度 6；内存顺序：

```
expected_tag[6] | entered_secret[48] | boundary_tag[6] | stored_secret[48] | stored_name[48] | entered_name[48]
```

**关键**：

- `expected_tag` 在 password 缓冲区**之前**，密码溢出不会碰它；
- `boundary_tag` 在 `entered_secret` 之后，会被 password 覆盖；
- 程序比较 `boundary_tag` 与 `expected_tag`；
- `expected_tag` 由 username 的**前 6 位学号数字**计算：

```
G_i = 'c' + d_i + 2i,  i = 0..5
```

（`d_i` 是学号第 i 位数字，`'c'` 是字符 c 的 ASCII 值；按题目/代码的字符运算实现。）

**参考结构**：

```
U = 学号 + 填充到 47 字符
P = 任意密码 + 填充到 47 字符
G = 上述 6 字节 tag

username = U
password = P ∥ F ∥ G ∥ P ∥ F ∥ U
```

- 长度：username 47，password 149；
- password 依次覆盖 `entered_secret`、`boundary_tag`、`stored_secret`、`stored_name`；
- 在 `boundary_tag` 的偏移放入 G，使 `boundary_tag == expected_tag`；
- `stored_name` 被 U 覆盖，`stored_secret` 被 P 覆盖；
- 终止符落在 `stored_name` 末尾，不会碰到 `entered_name`。

### 编程题易错点

| 错误 | 说明 |
|---|---|
| 直接抄 payload | 偏移依赖编译器/栈布局；换环境就失败 |
| username 不以学号开头 | 直接 0 分 |
| 用 `password.txt` 的内容 | 题目禁止；视为 secret |
| 忽略终止符 | 每个字段末尾的 `\0` 会改变比较结果 |
| 忘记 canary | login2/login3 的 tag 必须在正确位置保持相等 |
| 文件不是两行 | 提交要求严格：第一行 username、第二行 password |
