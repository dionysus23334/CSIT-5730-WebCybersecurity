## 题目 1 · 两种“扫代码”的方式

**换个说法**：反汇编有两种常见思路：一种是从头到尾按字节顺次扫（线性），一种是顺着跳转/调用一路跟（递归）。回答三个小问：

1. 顺着跳转扫，有什么坑？
2. 这个坑怎么补？
3. 开发者想让逆向更难受，可以做什么？

### (a) 顺着跳转扫的坑

- 它只跟**直接**跳转（`jmp`/`call`/`ret`）；
- 遇到**间接跳转**（`jmp %eax`、`call [eax]`、虚表）时，静态分析往往算不出目标；
- 结果：可能漏掉一部分本来可执行的代码，覆盖不全。

一句话：直接跳转能跟，间接跳转容易跟丢。

### (b) 怎么补

- **线性 + 递归结合**：递归没覆盖、但落在可执行段里的区域，用线性扫描补；
- 用常量传播/模拟执行解析一部分间接跳转；
- 用启发式/签名找函数入口、跳转表；
- 动态执行/插桩辅助确认哪些代码真的会跑。

### (c) 怎么让逆向更难

- 代码混淆（控制流平坦化、不透明谓词、指令替换）；
- 加壳/加密（packer）；
- 反汇编干扰（代码段里嵌数据）。

## 题目 2 · 恶意样本真的比正常软件多吗

**换个说法**：有人说，现在恶意样本的数量已经超过正常软件，签名库都快装不下了。回答：

1. 这话靠谱吗？
2. 如果真是这样，签名检测该怎么改？

### (a) 靠谱吗

**有可能**，但要看“怎么数”：

- 按**样本/变体**数：一个恶意程序可以自动生成大量多态/变形变种，数量很容易爆炸；
- 按**独立程序/家族**数：结论可能完全不同；
- 正常软件也有大量版本，但恶意样本的自动化变种成本更低。

所以，“恶意样本比正常软件多”在“按样本计数”的定义下是合理的；不要把它当成某个具体的全球统计结论。

### (b) 签名检测怎么改

传统签名是“列出坏的特征”。坏样本比好样本多时，签名库会爆炸。

**换个方向：以好软件为中心（allowlist）**

1. **可信哈希白名单**：只让已审核的可执行文件跑；
2. **未知文件隔离**：不在白名单 → 沙箱/隔离，而不是“没坏签名就放行”；
3. **白名单要防篡改**：签名、认证更新；
4. **审核流程**：新版本先审再加入；
5. **别把“批准”当“无漏洞”**：仍需行为监控和补丁管理。

核心：从“枚举坏”变成“只允许好”，并安全地处理未知。

## 题目 3 · `printf(name)` 的坑

**换个说法**：下面这种写法：

```c
char name[64];
scanf("%63s", name);
printf(name);
```

用户输入会直接被当成格式串。回答：

1. 用户能搞出什么事？
2. 除了读内存，还能写吗？
3. 怎么修？

### (a) 用户能搞出什么

- `printf` 把 `name` 当格式串；
- 输入 `%s%s%s` → `printf` 以为后面有三个字符串指针参数，从栈上取“参数”；
- 结果：把栈上的值当地址，打印其指向的内存 → **泄露内存**；非法地址 → 崩溃；
- `%x` 也会把栈上的数据打出来。

### (b) 能从读升级到写吗

能，用 **`%n`**：

```c
int val;
printf("blah %n blah\n", &val);
// val = 5（已输出 5 个字节）
```

- `%n` 把“已输出的字节数”写到对应参数指向的地址；
- 攻击者控制格式串，也就控制了 `printf` 从栈上取的“参数”；
- 于是可以指定目标地址（返回地址、flag、GOT 等），并用输出宽度控制写入值；
- 从信息泄露升级为**任意内存写**，进而劫持控制流。

### (c) 怎么修

1. 硬编码格式串：`printf("%s", name);`
2. 不需要格式化时用 `puts(name)`/`fputs`；
3. **绝不** `printf(user_input)`；
4. 禁用 `%n`；
5. 开编译器格式串告警、做代码审计。

核心：把格式串从用户手里拿走。

## 题目 4 · 编译器本身被做手脚

**换个说法**：一个团队审了编译器源码和账户检查程序源码，都没发现恶意代码。但他们现在用的编译器可执行文件 `C0` 被污染了，藏了两条规则：

- 编译“账户检查程序”源码时，往产物里插后门；
- 编译“编译器”源码时，把这两条规则也插进新编译器。

他们用 `C0` 编出 `C1`，再用 `C1` 编出账户检查程序 `A1`。回答：

1. `C1` 和 `A1` 干净吗？
2. 删掉 `C0`，用 `C1` 再编一个 `C2`，能解决吗？
3. 如果有一个独立可信的编译器 `T`，怎么重建？

### (a) C1 和 A1

- **C1 有隐藏规则**：`C0` 认出编译器源码，把两条规则插进 C1；
- **A1 有后门**：C1 认出账户检查源码，把后门插进 A1；
- 两份源码都干净，但行为通过编译器“继承”了。

### (b) 删 C0、编 C2

不能解决。C1 已经带规则，编编译器源码时会把同样的规则插进 C2；删 C0 只是删掉第一代二进制，后代仍然带毒。

**关键**：源码干净 ≠ 编出来的二进制干净；源码审计不能证明编译器忠实。

### (c) 用可信 T 重建

1. 在可信环境里，用 `T` 编译“编译器源码” → 干净的 `C_clean`；
2. 用 `C_clean`（或直接用 `T`）编译“账户检查源码” → 干净的 A；
3. **替换所有受影响的二进制**，不只是删 C0 或改源码；
4. 最好用可复现构建/多样化双编译，防止再次被污染。

关键：换掉“被污染的构建产物”，从可信根重建工具链。

## 题目 5 · 三个登录程序（溢出思路）

**换个说法**：有三个登录程序，都从命令行拿 username/password，和文件里的 secret 比。目标是用溢出绕过检查，看到登录成功。三个版本分别加了不同防护：

- login1：没有 canary；
- login2：固定 canary（一个固定字节/标记）；
- login3：用 username 算出来的 canary。

下面只讲**栈布局和思路**，不写可直接抄的 payload；实际偏移要自己用调试器/反汇编确认。

> 课程还要求 username 以自己的学号开头，且不能使用 `password.txt` 里的内容；这里不展开。

### login1

**布局**：几个字段在栈上连续排：

```
entered_name | entered_secret | stored_name | stored_secret
```

**思路**：

- username 只填 `entered_name`，长度刚好不越界；
- password 从 `entered_secret` 开始写，会**越过**自己的缓冲区，覆盖后面的 `stored_name` 和 `stored_secret`；
- 程序会在每个字段末尾写终止符；用 filler 把多余字符“顶掉”；
- 比较时 `entered_name == stored_name`、`entered_secret == stored_secret`，于是通过。

**要点**：不是改比较逻辑，而是**把“标准答案”改成你输入的值**。

### login2

**布局**：字段和两个标记交错：

```
entered_name | stored_name | tag1 | stored_secret | tag2 | entered_secret
```

- `tag1`、`tag2` 初始相等；
- username 要覆盖 `stored_name`、`tag1`、`stored_secret`、`tag2`，同时让两个 tag 仍然相等；
- password 只负责填 `entered_secret`。

**思路**：

- 用 filler + 你选的 username/password 覆盖 stored 字段；
- 在两个 tag 的位置都放上**相同的值**（比如原来的固定值，或同一个非零字节）；
- 这样 canary 检查通过，比较也通过。

**要点**：canary 是“固定值”，只要在正确偏移把它写回同样的值即可。

### login3

**布局**：tag 在 password 缓冲区的前后都有：

```
expected_tag | entered_secret | boundary_tag | stored_secret | stored_name | entered_name
```

- `expected_tag` 在 password 缓冲区**之前**，密码溢出碰不到它；
- `boundary_tag` 在 `entered_secret` 之后，会被 password 覆盖；
- 程序比较 `boundary_tag` 和 `expected_tag`；
- `expected_tag` 是由 username 的前几位学号数字**算出来**的，所以不能写死。

**思路**：

1. username 填 `entered_name`；
2. password 从 `entered_secret` 开始，依次覆盖 `boundary_tag`、`stored_secret`、`stored_name`；
3. 用学号数字按程序里的公式算出 6 字节 tag `G`；
4. 在 `boundary_tag` 对应的偏移放 `G`，让 `boundary_tag == expected_tag`；
5. 在 `stored_name` 放你的 username，在 `stored_secret` 放你的 password；
6. 终止符落在 `stored_name` 末尾，不要碰到 `entered_name`。

**要点**：动态 canary 不是“不能绕”，而是**要按程序自己的算法算出来**；关键是找到 `boundary_tag` 的偏移。

### 编程题易错点

| 坑 | 说明 |
|---|---|
| 直接抄 payload | 偏移随编译器/栈布局变，换环境就废 |
| username 不带学号 | 课程要求，直接没分 |
| 用 `password.txt` 的内容 | 题目禁止，视为 secret |
| 忽略终止符 | 每个字段末尾的 `\0` 会改变比较 |
| canary 位置写错 | login2 要两个 tag 相等；login3 要放算出来的 G |
| 文件格式不对 | 两行：第一行 username，第二行 password |
