## 题目 1 · 会“走位”的凯撒

**换个说法**：普通的凯撒是每个字母都挪同样的格数。现在改成：第 1 个字母挪 13 格，第 2 个挪 14 格，第 3 个挪 15 格……依次加 1。用 A–Z，超了就绕回来。把 `SECURITY` 加密，看看每个字母挪了几格、最后长什么样。

**怎么做**

- 字母编号 `A=0,...,Z=25`；
- 第 i 个字母（i 从 0 开始）移 `13+i`；
- `C = (P + 13 + i) mod 26`。

**结果**

| 位置 | 明文 | 值 | 移位 | 密文 |
|---|---|---|---|---|
| 1 | S | 18 | 13 | **F** |
| 2 | E | 4 | 14 | **S** |
| 3 | C | 2 | 15 | **R** |
| 4 | U | 20 | 16 | **K** |
| 5 | R | 17 | 17 | **I** |
| 6 | I | 8 | 18 | **A** |
| 7 | T | 19 | 19 | **M** |
| 8 | Y | 24 | 20 | **S** |

密文是 **`FSRKIAMS`**。

**容易错**：移位是按位置递增的，不是固定 13；`S` 是 18，`18+13=31`，`31 mod 26 = 5`，对应 F。

## 题目 2 · OTP 反推

**换个说法**：还是用那套 3-bit 字母编码：`e=000, f=001, h=010, i=011, k=100, l=101, r=110, t=111`。OTP 的规则就是 `C = P ⊕ K`。

### (a) 知道明文和密文，倒推密钥

明文 `hike`，密文 `left`，求密钥。

`K = P ⊕ C`：

| | 字符 | 比特 |
|---|---|---|
| 明文 | h i k e | 010 011 100 000 |
| 密文 | l e f t | 101 000 001 111 |
| 密钥 | **t i l t** | **111 011 101 111** |

密钥是 **`tilt`**。

### (b) 知道密钥和密文，倒推明文

密钥 `keel`，密文 `rile`，求明文。

`P = C ⊕ K`：

| | 字符 | 比特 |
|---|---|---|
| 密文 | r i l e | 110 011 101 000 |
| 密钥 | k e e l | 100 000 000 101 |
| 明文 | **h i l l** | **010 011 101 101** |

明文是 **`hill`**。

**容易错**：按字符查表时 `i=011`、`l=101`，别抄串；XOR 两次会还原。

## 题目 3 · 暴力搜 key 要多久

**换个说法**：假设一台机器每秒能试 `2^15` 个 key。

### (a) 80-bit key，最坏情况

- 最坏要把 `2^80` 个 key 都试一遍；
- 时间 `2^80 / 2^15 = 2^65` 秒；
- 一年约 `3.1536×10^7` 秒；
- `2^65 / 3.1536×10^7 ≈ 1.17×10^12` 年。

**结果**：约 **2⁶⁵ 秒 ≈ 1.17×10¹² 年**。

### (b) 50-bit key，平均情况

- 平均试一半，也就是 `2^49` 个；
- `2^49 / 2^15 = 2^34` 秒；
- `2^34 / 3.1536×10^7 ≈ 544` 年。

**结果**：约 **2³⁴ 秒 ≈ 544 年**。

**容易错**：平均情况用 `2^49`，不是 `2^50`；换算别把秒当年。

## 题目 4 · 这个 CTR 写法靠谱吗

**换个说法**：正常 CTR 是 `C_i = P_i ⊕ E(IV+i, K)`。有人写成了：

```
C_i = P_i ⊕ E(K, IV+i)
```

注意这里 `E(明文, 密钥)`：`K` 被放到了“明文”的位置，`IV+i` 反而成了“密钥”。这安全吗？

**关键**：`IV+i` 是公开的，等于加密用的“密钥”是公开的；而 `K` 被当成明文加密了。

**攻击（已知一对明文/密文）**

1. 由 `C_i = P_i ⊕ E(K, IV+i)` 得：
   ```
   P_i ⊕ C_i = E(K, IV+i)
   ```
2. 因为 `IV+i` 公开，攻击者知道解密用的 key；
3. 直接解：
   ```
   K = D(P_i ⊕ C_i, IV+i)
   ```
4. 拿到 K 后，任意块都能解：
   ```
   P_j = C_j ⊕ E(K, IV+j)
   ```

**结论**：**不安全**。不是“用了 K 就安全”，要看 K 到底在哪个参数位置。

## 题目 5 · 有 MAC 和 key，能不能造新消息

**换个说法**：CBC-MAC 的做法是：

```
C_0 = E(IV ⊕ P_0, K)
C_i = E(C_{i-1} ⊕ P_i, K)
MAC = C_{n-1}
```

现在你知道 MAC 值 `X`，也知道 key `K`，但不知道原来那条消息。能不能拼一条新消息，让它的 MAC 还是 `X`？

### (a) 构造

1. 前 `n-1` 块 `P_0,...,P_{n-2}` 随便选；
2. 算出它们的链值 `C_{n-2}`；
3. 最后一块令：
   ```
   P_{n-1} = D(X, K) ⊕ C_{n-2}
   ```
4. 验证：
   ```
   MAC = E(P_{n-1} ⊕ C_{n-2}, K)
       = E(D(X,K), K)
       = X
   ```

**结论**：能。消息 `(P_0,...,P_{n-1})` 的 MAC 仍然是 X。

### (b) 自由选多少块

- 除了**最后一块**，前面的块都能自由选；
- 最后一块由前缀、IV、K 和目标 MAC 唯一决定。

**顺带一句**：这正说明 MAC 不能抗“知道 key 的人”伪造；它不是数字签名。

## 题目 6 · CBC 能不能随机读

**换个说法**：CBC 加密是一块套一块的。如果只想读第 i 块，需要哪些东西？和 CTR 比，随机改一块是不是更麻烦？

**读一块**

```
P_i = D(C_i, K) ⊕ C_{i-1}
```

- 需要 `C_i` 和前一块 `C_{i-1}`；
- 第 0 块用 IV 顶替 `C_{-1}`。

**和 CTR 的差别**

- CBC：改 `P_i` 会让 `C_i` 变，后面的链值全变；要保住后面的明文，得把 i 之后的密文全部重算。
- CTR：`C_i = P_i ⊕ E(IV+i, K)`，每块独立；改一块不影响别的块。

**结论**：CBC 随机读还行（多拿前一块），随机写/更新代价大；CTR 更适合随机访问。

## 题目 7 · 在 CBC 里把 P1 换成 X

**换个说法**：Alice 用 CBC 发了 4 块密文和 IV。Trudy 能在传输中改密文。如果她知道 `P1`，有没有办法让 Bob 解出来的 `P1` 变成 `X`？

**做法**：改 `C0`：

```
C0' = C0 ⊕ P1 ⊕ X
```

**为什么**

```
P1' = D(C1, K) ⊕ C0'
    = D(C1, K) ⊕ C0 ⊕ P1 ⊕ X
    = P1 ⊕ P1 ⊕ X
    = X
```

**副作用**：`C0` 变了，`P0` 也会乱（`P0 = D(C0',K) ⊕ IV`）。题目只关心 P1，所以可以接受。

**结论**：CBC 加密不保完整性；知道某块明文，就能定向改它。

## 题目 8 · RSA 的同态小把戏

**换个说法**：Trudy 拿到两条用 Alice 公钥加密的密文 `C0 = M0^e mod N`、`C1 = M1^e mod N`。她不知道私钥，也不知道明文。

### (a) 能不能算出 `(M0·M1)^e mod N`？

能，直接把两条密文乘起来：

```
C0·C1 ≡ M0^e · M1^e ≡ (M0·M1)^e (mod N)
```

所以结果是 `C0·C1 mod N`。

### (b) 那 `(M0+M1)^e mod N` 呢？

一般不能。RSA 只有**乘法同态**，没有加法同态；`M0^e + M1^e` 通常不等于 `(M0+M1)^e`。特殊情况和穷举另说，但没有类似的简单代数操作。

### (c) 全同态加密（FHE）有什么用？

- 把加密数据交给不可信服务器做计算（统计、机器学习、检索）；
- 服务器看不到明文，只返回加密结果；
- 适合医疗、金融、基因等隐私敏感场景。

一句话：**计算外包，但数据不裸奔。**

## 题目 9 · 签名能不能被“反着用”

**换个说法**：协议是 Alice 用自己的私钥签 `M`，发 `(M,S)`；Bob 用 Alice 公钥验。Trudy 能不能让 Bob 接受一条 Alice 根本没签过的消息？

### (a) 这个伪造严重吗

Trudy 可以：

1. 随便选一个 `R`；
2. 算 `N = {R}Alice`（用 Alice 公钥“加密”R）；
3. 把 `(N, R)` 发给 Bob；
4. Bob 验证 `{R}Alice = N`，于是认为 `N` 是 Alice 签的消息。

**性质**：

- 这是**存在性伪造**：Trudy 不能自由选择有意义的 `N`，只能得到“R 的公钥加密结果”；
- 但 Bob 确实接受了一条 Alice 没签过的消息；
- 如果系统会把 `N` 当命令、金额、文件名来解释，就可能出实际问题。

**结论**：是安全性问题，不只是恶作剧；只是“随机消息”限制了它的直接利用。

### (b) 改成签 `F(M)` 后，F 要满足什么

协议变成：

```
S = [F(M)]Alice
Bob 验证：{S}Alice = F(M)
```

Trudy 选 R，算出 `Y = {R}Alice`，现在她得找一个 `M` 使 `F(M) = Y`，才能把 `(M,R)` 发过去。

所以 `F` 必须**单向（preimage-resistant）**：

> 给定 Y，想反推出 M 使 `F(M)=Y`，计算上不可行。

这样 Trudy 就没法把任意 Y 变成合法消息。实际中会用抗碰撞的哈希（如 SHA-256）；单向性挡住这个伪造，抗碰撞性防止“换消息”。

## 题目 10 · 哈希碰撞的“保证数”

**换个说法**：一个哈希输出 n bit，最多有 `2^n` 种结果。现在想**保证**能找到 10 对不同输入碰撞（不同对可以共用输入），最多需要试多少个不同输入？

**答案**：`2^n + 10`。

**为什么**

- 输出只有 `2^n` 个桶；
- 试 `2^n + 10` 个输入，按鸽巢原理，至少有 10 个“多出来”的输入落在已经有人的桶里；
- 每多一个这样的输入，至少新增一对碰撞（它和桶里已有的某个输入）；
- 所以至少 10 对。

**为什么不能更少**：`2^n + 9` 时，可以让 9 个桶各放 2 个，其余桶各 1 个；这样总共只有 9 对，不够 10 对。

**容易错**：这里问的是“保证”（最坏情况），不是生日攻击的“期望” `2^{n/2}`。

## 题目 11 · 加密和哈希差在哪

挑 3 条说清楚即可：

| 维度 | 加密 | 哈希 |
|---|---|---|
| **key** | 通常有 key | 普通密码学哈希没有 key |
| **可逆** | 能解密回明文 | 单向，回不去 |
| **输出** | 密文通常和明文差不多长 | 任意长度 → 固定长度 |
| **映射** | 固定 key 下应可逆 | 多对一，必然有碰撞 |
| **目的** | 保密 | 完整性/指纹/口令存储 |

一句话：加密是“可逆地藏起来”，哈希是“不可逆的指纹”。
