## Q1（5 分）改进版凯撒密码

**题目**：第 1 个字母移 13 位，第 2 个移 14 位，第 3 个移 15 位……加密 `SECURITY`。

**思路**

- 字母编号 `A=0,...,Z=25`。
- 第 i 个字母（从 0 开始）移 `13+i` 位：`C = (P + 13 + i) mod 26`。
- 逐个算，注意 `Z→A` 回绕。

**答案**

| 位置 | 明文 | 值 | 移位 | 密文 |
|---|---|---|---|---|
| 1 | S | 18 | 13 | **F** |
| 2 | E | 4 | 14 | **S** |
| 3 | C | 2 | 15 | **R** |
| 4 | U | 20 | 16 | **K** |
| 5 | R | 17 | 17 | **I** |
| 6 | I | 8 | 18 | **A** |
| 7 | T | 19 | 19 | **M** |
| 8 | Y | 24 | 20 | **S** |

密文：**`FSRKIAMS`**。

**易错**：移位要按位置递增，不是固定 13；`S+13=31 mod 26=5=F`。

## Q2（6 分）OTP 的密钥与明文

编码表：`e=000, f=001, h=010, i=011, k=100, l=101, r=110, t=111`。

### (a) 已知明文 `hike`、密文 `left`，求密钥

OTP：`C = P ⊕ K` ⇒ `K = P ⊕ C`。

| | 字符 | 比特 |
|---|---|---|
| 明文 | h i k e | 010 011 100 000 |
| 密文 | l e f t | 101 000 001 111 |
| 密钥 | **t i l t** | **111 011 101 111** |

密钥：**`tilt`**。

### (b) 已知密钥 `keel`、密文 `rile`，求明文

`P = C ⊕ K`。

| | 字符 | 比特 |
|---|---|---|
| 密文 | r i l e | 110 011 101 000 |
| 密钥 | k e e l | 100 000 000 101 |
| 明文 | **h i l l** | **010 011 101 101** |

明文：**`hill`**。

**易错**：XOR 两次还原；字符→比特表不要抄错（`i=011`、`l=101`）。

## Q3（6 分）穷举时间

机器速度：**2¹⁵ 个密钥/秒**。

### (a) 80-bit 密钥，最坏情况

- 最坏要试 `2⁸⁰` 个密钥。
- 时间 `2⁸⁰ / 2¹⁵ = 2⁶⁵` 秒。
- 换算年：`2⁶⁵ / (3600×24×365) ≈ 1.17×10¹²` 年。

**答案**：约 **2⁶⁵ 秒 ≈ 1.17×10¹² 年**。

### (b) 50-bit 密钥，期望情况

- 平均试一半：`2⁴⁹` 个。
- 时间 `2⁴⁹ / 2¹⁵ = 2³⁴` 秒。
- 换算：`2³⁴ / 3.1536×10⁷ ≈ 544` 年。

**答案**：约 **2³⁴ 秒 ≈ 544 年**。

**易错**：期望时间用 `2⁴⁹` 不是 `2⁵⁰`；单位换算是秒→年。

## Q4（4 分）这个 CTR 变体安全吗？

**题目**：`C_i = P_i ⊕ E(K, IV+i)`，其中 `E(P,K)` 表示“明文 P、密钥 K”。

**关键**：`E(K, IV+i)` 把 **K 当作明文**、把 **公开的 IV+i 当作密钥**。

**攻击（已知明文）**

1. 已知一对 `(P_i, C_i)`：
   ```
   P_i ⊕ C_i = E(K, IV+i)
   ```
2. 由于 `IV+i` 是公开的，攻击者知道加密时用的“密钥”；
3. 用 `D(·, IV+i)` 解密：
   ```
   K = D(P_i ⊕ C_i, IV+i)
   ```
4. 恢复 K 后，对任意块：
   ```
   P_j = C_j ⊕ E(K, IV+j)
   ```

**结论**：**不安全**。密钥 K 被当作明文加密，而“加密密钥”是公开的 IV；一次已知明文即可恢复 K。

**易错**：不要以为“E 里面用了 K”就安全；要看 K 是作为明文还是密钥。

## Q5（6 分）已知 MAC 和密钥，伪造消息

**背景**：CBC-MAC：

```
C_0 = E(IV ⊕ P_0, K)
C_i = E(C_{i-1} ⊕ P_i, K)
MAC = C_{n-1}
```

已知 `MAC = X`、密钥 `K`，但不知道原消息。

### (a) 构造一个新消息，使 MAC 仍为 X

1. 自由选择前 `n-1` 个块 `P_0,...,P_{n-2}`；
2. 计算它们的 CBC 链，得到 `C_{n-2}`；
3. 令最后一块：
   ```
   P_{n-1} = D(X, K) ⊕ C_{n-2}
   ```
4. 则：
   ```
   MAC = E(P_{n-1} ⊕ C_{n-2}, K)
       = E(D(X,K), K)
       = X
   ```

**答案**：消息 `M = (P_0,...,P_{n-1})` 的 MAC 仍为 X。

### (b) 有多少块可以自由选？

- **除最后一块外**，所有块都可自由选择；
- 最后一块由前缀、IV、K、目标 MAC 唯一确定。

**结论**：知道 K 就能伪造任意前缀的“同 MAC”消息；MAC 不能抗拥有密钥者的伪造（这不是签名）。

## Q6（4 分）CBC 的随机访问

**读一个块**

```
P_i = D(C_i, K) ⊕ C_{i-1}
```

- 需要 `C_i` 和前一块 `C_{i-1}`；
- 第 0 块用 IV 代替 `C_{-1}`。

**与 CTR 比较的缺点**

- CBC：修改 `P_i` 会改变 `C_i`，进而改变后续所有 `C_{i+1},...` 的链值；要保留后续明文，必须**重算从 i 到末尾的所有密文**。
- CTR：`C_i = P_i ⊕ E(IV+i,K)`，每块独立；改一块不影响其他块。

**结论**：CBC 可以随机**读**（需要前一块），但随机**写/更新**代价大；CTR 更适合随机访问。

## Q7（6 分）CBC 比特翻转：把 P1 换成 X

**已知**：

```
P_1 = D(C_1,K) ⊕ C_0
```

**目标**：让 Bob 解密 `C_1` 时得到 X。

**做法**：把 `C_0` 替换为

```
C_0' = C_0 ⊕ P_1 ⊕ X
```

**验证**：

```
P_1' = D(C_1,K) ⊕ C_0'
     = D(C_1,K) ⊕ C_0 ⊕ P_1 ⊕ X
     = P_1 ⊕ P_1 ⊕ X
     = X
```

**副作用**：`C_0` 变了，`P_0` 也会变乱（`P_0 = D(C_0',K) ⊕ IV`），但题目只要求改 `P_1`。

**结论**：CBC 加密不提供完整性；攻击者知道 P1 就能定向篡改 P1。

## Q8（6 分）RSA 的乘法同态

已知 `C_0 = M_0^e mod N`，`C_1 = M_1^e mod N`。

### (a) 求 `(M_0·M_1)^e mod N`

```
C_0·C_1 ≡ M_0^e · M_1^e ≡ (M_0·M_1)^e (mod N)
```

所以 `(M_0·M_1)^e mod N = C_0·C_1 mod N`。

### (b) 能否求 `(M_0+M_1)^e mod N`？

- **一般不能**通过类似的简单代数运算得到；
- RSA 只有**乘法同态**，没有加法同态；
- `M_0^e + M_1^e` 通常不等于 `(M_0+M_1)^e`。

### (c) 全同态加密（FHE）的用途

- 不可信服务器对**加密数据**做计算（统计、机器学习、检索）；
- 医疗记录、金融数据、基因数据等隐私敏感场景；
- 服务器返回加密结果，数据所有者解密；服务器全程看不到明文。

**一句话**：FHE 让“计算外包”不必以泄露数据为代价。

## Q9（14 分）签名伪造与 `F(M)`

### (a) 这个攻击严重吗？

**攻击**：

1. Trudy 任选 R；
2. 计算 `N = {R}Alice`（用 Alice 公钥“加密”R）；
3. 发送 `(N, R)`；
4. Bob 验证 `{R}Alice = N`，认为 N 是 Alice 签名的消息。

**性质**：

- 这是**存在性伪造（existential forgery）**：Trudy 不能自由选择有意义的 N，只能让 N 是“R 的公钥加密结果”；
- 但 Bob 确实接受了一个 Alice 从未签过的消息；
- 如果系统对 N 有语义解释（命令、金额、文件名），可能造成实际危害；
- 因此**是安全性问题**，不只是“恶作剧”；只是“随机消息”限制了即时利用。

### (b) 改成签 `F(M)` 后，F 要满足什么条件？

协议：

```
S = [F(M)]Alice
Bob 验证：{S}Alice = F(M)
```

**攻击者**：

- 选 R，算 `Y = {R}Alice`；
- 现在需要找 M 使 `F(M) = Y`，才能把 `(M,R)` 发给 Bob。

**条件**：`F` 必须是**单向（preimage-resistant）**的：

> 给定 Y，找到 M 使 `F(M)=Y` 在计算上不可行。

这样 Trudy 无法把任意 Y 变成合法的 M。

**补充**：实际用**抗碰撞哈希**（SHA-256 等）更稳妥；单向性阻止上述伪造，抗碰撞性防止“换消息”。

## Q10（2 分）哈希碰撞的鸽巢界

**题目**：n-bit 哈希（n≥4），保证出现 **10 对不同碰撞**，最多需要哈希多少个不同输入？

**答案**：**`2^n + 10`**。

**理由**：

- 哈希输出只有 `2^n` 种；
- 若哈希 `2^n + 10` 个不同输入，按鸽巢原理，至少有 10 个“多余”的输入落在已有输出的桶里；
- 每多一个输入落到某个桶，至少新增一对碰撞（该输入与桶里已有的某个输入）；
- 因此至少 10 对（不同对可共享输入）。

**紧性**：`2^n + 9` 不够——可以让 9 个输出各出现 2 次，其余输出各 1 次，总共只有 9 对碰撞。

**易错**：不是 `10×2^n`；也不是“生日界”的 `2^{n/2}`，这里问的是**保证**（最坏情况），不是期望。

## Q11（6 分）加密与哈希的区别

任选 3 条，每条 2 分：

| 维度 | 加密 | 哈希 |
|---|---|---|
| **密钥** | 通常有密钥 | 普通密码学哈希无密钥 |
| **可逆性** | 可解密还原明文 | 单向，不能还原 |
| **输入/输出** | 明文长度可变，密文通常等长/略长 | 任意长度 → 固定长度摘要 |
| **映射** | 固定密钥下应可逆，不同明文不应同密文 | 多对一，必然有碰撞 |
| **目的** | 机密性 | 完整性、指纹、口令存储 |

**一句话**：加密是“可逆的隐藏”，哈希是“不可逆的指纹”。
